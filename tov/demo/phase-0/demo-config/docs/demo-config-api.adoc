[[overview]]
== Overview

[.lead]
The `demo-config` programfootnote:[Binary path: `tov/demo/phase-0/demo-config/bin/demo-config`] validates the {phase} TOML specifications by loading and displaying all {system-count} system categories. It provides a **portable public API** in Go that can be called by other programs.

[IMPORTANT]
====
*{the-purpose}* {the-pattern}
====

// ─────────────────────────────────────────────────────────────────────────────
// SCOPE — What this API provides
// ─────────────────────────────────────────────────────────────────────────────

****
[.lead]
*What this API provides:*

[horizontal]
icon:check-circle[] *Validation*:: Validate all {system-count} systems via `DemoConfigRunAll()`
icon:crosshairs[] *Tripwire*:: Manifest vs filesystem verification
icon:sitemap[] *Dependencies*:: Dependency graph validation (no cycles)
icon:balance-scale[] *Ternary Status*:: PASS (+1), HALF PASS (0), FAIL (-1)
icon:stethoscope[] *Diagnostics*:: Building block APIs for debugging
icon:link[] *Chain*:: link:{loader-go}[loader.go] → link:{loader-test}[loader_test.go] → link:../main.go[main.go]
****

=== The Chain Pattern

****
[.lead]
*How the diagnostic APIs work:*

The diagnostic APIs aren't standalone — they're building blocks used by the validation logic:

[source]
----
loader.go (exports APIs)
    ↓ config.DiscoverAndCompare(), config.ValidateDependencyGraph(), etc.
loader_test.go (TestDiagnostic uses same APIs)
    ↓ returns test results
demo_config.go (Diagnostic APIs as building blocks)
    ├── DemoConfigDiagnosticTripwire(verbose) → returns DiscoveryResult
    ├── DemoConfigDiagnosticDeps(verbose) → returns []error
    └── DemoConfigDiagnosticLoad(verbose) → returns LoadResult
        ↓
    demoValidatePrerequisites() → USES those APIs (no duplicate calls)
----

[NOTE]
====
*Why this matters (Bootstrapping):* We're building validation/debugging infrastructure NOW (while still Go/C/TOML) so the patterns become native to OmniCode. The diagnostic infrastructure grows WITH the system, not bolted on after.
====
****

=== Quick Start

*Get started in 10 lines:*

[source,go]
----
import demo "creativeworkzstudio.com/bereshit/tov/demo/phase-0/demo-config"

func main() {
    // Run all system validations
    failures := demo.DemoConfigRunAll()

    if failures == 0 {
        fmt.Println("All 9 systems validated!")
    }

    // Check ternary status
    status := demo.DemoConfigGetStatus()
    switch status {
    case 1:  fmt.Println("PASS (+1): Primary path works")
    case 0:  fmt.Println("HALF PASS (0): Fallback works")
    case -1: fmt.Println("FAIL (-1): System broken")
    }

    // If something fails, run diagnostic
    if status < 1 {
        demo.DemoConfigDiagnostic() // Full debug output
    }

    // Reset for another run
    demo.DemoConfigReset()
}
----
****

[[diagnostic-apis]]
=== Diagnostic APIs (Building Blocks)

****
[.lead]
*Deep debugging tools:*

These functions return data AND can print. They're building blocks used by the validation logic.

[source,go]
----
func DemoConfigDiagnostic() int                                    // Run all phases, return status
func DemoConfigDiagnosticIndex(verbose bool) config.LoadResult     // Phase 1: index health
func DemoConfigDiagnosticTripwire(verbose bool) (config.DiscoveryResult, error)  // Phase 2: tripwire
func DemoConfigDiagnosticDeps(verbose bool) ([]error, error)       // Phase 3: dependency graph
func DemoConfigDiagnosticLoad(verbose bool) config.LoadResult      // Phase 4: config loading
----

[horizontal]
icon:toggle-on[] *verbose=true*:: Print diagnostic output AND return data
icon:toggle-off[] *verbose=false*:: Just return data (silent mode)

[NOTE]
====
*Usage:* When `demoValidatePrerequisites()` runs, it calls these with `verbose=false` to get data, then formats its own output. For debugging, call `DemoConfigDiagnostic()` directly to see all phases.
====
****
