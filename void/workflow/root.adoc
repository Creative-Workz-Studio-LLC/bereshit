[[structure]]
== Structure & Flow

Workflow files follow a consistent structure — each workflow is a .jsonc file with metadata, core patterns, and steps.

[[flow]]
=== Workflow Structure

----
    workflow/
        ├── root.omni           # Folder metadata
        ├── root.adoc           # This documentation
        ├── file-creation-workflow.jsonc
        ├── alignment-workflow.jsonc
        ├── commit-workflow.jsonc
        └── block-update-workflow.jsonc
----

*The workflow lifecycle:*

. Pattern emerges through repeated practice
. Pattern is recognized and documented
. Workflow file created with steps and insights
. Workflow refined as understanding deepens
. Mature workflows may move to word/ as standards

[TIP]
====
*Workflows are building blocks.* Each workflow captures a reusable pattern that can be referenced, refined, and combined with other workflows.
====

[%collapsible]
.Deep Dive: Why Workflows in Void?
====
Workflows live in void because they are *forming* — patterns still being discovered and refined.

**The lifecycle:**

[cols="^1,2,3",options="header"]
|===
| State | Location | Status

| Forming
| void/workflow/
| Pattern emerging, being documented

| Established
| word/standards/ (future)
| Pattern proven, ready for standardization

| Applied
| Throughout codebase
| Pattern in active use
|===

**Why this matters:**

* Workflows here are *learning records*, not fixed standards
* They can be wrong, incomplete, or need revision
* Moving to word/ signifies the pattern is proven

**Practice over theory** — We don't write workflows we *plan* to follow. We document workflows we *already* follow.
====

[[workflow-health]]
=== Workflow Health

Workflow health measures documentation completeness, not pattern correctness.

[cols="^1,2,3",options="header"]
|===
| State | Indicator | Meaning

| *Healthy (+1)*
| All workflows documented
| Patterns captured and usable

| *Forming (0)*
| Some workflows incomplete
| Patterns being discovered

| *Outdated (-1)*
| Workflows don't match practice
| Documentation drift
|===

[[biblical-foundation]]
== Biblical Foundation

[NOTE]
====
*Labour (מַעֲשֶׂה ma'aseh)* means "work, deed, action" — patterns emerge from doing.
====

_"In all labour there is profit: but the talk of the lips tendeth only to penury."_ — *Proverbs 14:23*

*Applied:* Workflows are documented from practice, not theory. We don't write workflows we plan to follow — we document workflows we already follow. The profit is in the doing, and documentation captures what works.

[%collapsible]
.Deep Dive: The Wisdom of Practice
====
**Documentation follows practice.**

Proverbs 14:23 distinguishes between *labour* (actual work) and *talk of the lips* (theory without action). Workflows in void/ are the former — patterns discovered through work.

**Why practice first:**

[cols="^1,3,3",options="header"]
|===
| Order | What Happens | Result

| 1st
| Do the work
| Pattern emerges naturally

| 2nd
| Recognize the pattern
| Conscious awareness of what works

| 3rd
| Document the pattern
| Reusable building block
|===

**Applied to workflows:**

* Workflows here are *learning records*, not prescriptions
* They capture what we actually do, not what we think we should do
* Refinement comes from continued practice, not initial design
* Moving to word/ means the pattern is proven

**The spiritual principle:**

James 1:22 says "Be ye doers of the word, and not hearers only." Workflows embody this — they document *doing*, enabling others to do likewise.
====
