[[what-was-built]]
== What Was Built

Crystallization infrastructure — single source of truth, tripwire pattern, master template, manifest-driven loading.

=== Tripwire Pattern

Both generator and loader follow the same pattern:

[source]
----
Primary:   Try index.toml first (single source of truth)
Tripwire:  If index.toml missing, LOUDLY warn
Fallback:  Use hardcoded paths (graceful degradation)
Error:     Only if actual files don't exist
----

The LOUD warning ensures you know you're in degraded mode — not silent fallback.

=== Generator: Master Template

Stripped specific templates (`ternaryMathTemplate`, `scriptureTextTemplate`). One master template handles all TOMLs via `[_generate]` metadata:

[cols="2,4",options="header"]
|===
| Field | Purpose

| `guard` | Header guard name (e.g., `TERNARY_MATH_GEN_H`)
| `output` | Output filename (e.g., `ternary_math.gen.h`)
| `sections` | Which TOML sections to process
| `arrays` | Which fields need C array formatting
|===

Dotted section paths like `"operations.half_adder"` navigate nested TOML tables and produce `HALF_ADDER_` prefixes.

=== Loader: Manifest-Driven

Stripped hardcoded Load* implementations. New generic functions:

[cols="2,4",options="header"]
|===
| Function | Purpose

| `LoadSystem(name)` | Load all specs in a system by name
| `LoadSpec(system, spec)` | Load single spec from a system
| `LoadIndex()` | Expose manifest for external tools
|===

Thin wrappers (`LoadMath()`, `LoadBible()`, etc.) delegate to `LoadSystem()` — typed access without duplication.

=== By The Numbers

[cols="2,4",options="header"]
|===
| Metric | Value

| *Generator templates*
| 1 master (was 3+)

| *Loader Load* functions*
| 2 generic + 9 thin wrappers (was 9 specific)

| 3 (ternary.toml, primitives.toml, scripture-text.toml)

| All pass (250+)
|===

[[what-emerged]]
== What Emerged

What revealed itself through implementation — connections not initially obvious.

=== Single Source of Truth Enables Both

When `index.toml` became the manifest for BOTH loader and generator, coordination became automatic:

* Add new TOML to index.toml → both tools pick it up
* No separate registration in Go code
* Manifest IS the configuration

=== Tripwire Pattern as Grace

The tripwire pattern isn't just error handling — it's designed **expecting faults**:

* Primary path works when everything is right
* Tripwire catches when config is missing — LOUDLY
* Fallback allows work to continue in degraded mode
* Error only for actual file absence

This mirrors the Detect-Assess-Recover pattern from building blocks.

=== [_generate] as Self-Description

Each TOML now describes how it should be processed:

[source,toml]
----
[_generate]
enabled = true
output = "ternary_math.gen.h"
guard = "TERNARY_MATH_GEN_H"
sections = ["trit", "packing", "operations.half_adder"]
arrays = ["values", "sum", "carry"]
----

The TOML knows its own generation requirements — generator doesn't hardcode them.

=== Dotted Paths for Nested Tables

`"operations.half_adder"` navigates TOML structure AND creates C prefix (`HALF_ADDER_`):

* Template function `sectionName` extracts last part
* Template function `getSection` navigates nested tables
* Nested structure → flat C output with meaningful prefixes

[[what-was-discovered]]
== What Was Discovered

Deeper learnings about the process itself.

=== Look Before You Leap

Rushed to create devlog-007, when devlogs 007 and 008 already existed. Seanje caught it: "You looked at what existed first instead of rush through."

The discipline applies everywhere — not just code:

* Check what exists before creating
* Read before writing
* Grep before glob

=== Tripwire Needs Loud Warning

Initial fallback was silent. Seanje pushed: "If index.toml is missing, LOUDLY warn."

Silent fallback hides problems. Loud fallback:

* Makes degraded mode obvious
* Doesn't block work
* But ensures you KNOW something's wrong

=== Master Template Eliminates Duplication

Each specific template was 90% identical. The master template:

* Handles any TOML with `[_generate]` metadata
* Specifics come from the TOML itself
* New TOMLs don't require Go changes

Adding a new generated header: add `[_generate]` section → done.

=== Manifest-Driven Loading Parallels Generation

The loader and generator now follow the same pattern:

[cols="2,2,2",options="header"]
|===
| Aspect | Generator | Loader

| *Source of Truth*
| index.toml
| index.toml

| *Primary Path*
| Walk manifest, generate
| Walk manifest, load

| *Tripwire*
| LOUD warning if missing
| LOUD warning if missing

| *Fallback*
| Hardcoded system paths
| Hardcoded system paths
|===

Same pattern, different purpose. Consistency enables understanding.
