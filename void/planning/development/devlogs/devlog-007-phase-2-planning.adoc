[[what-emerged]]
== What Emerged

What revealed itself through the planning discussion — connections not initially obvious.

=== Calculus Is Required

Through discussion, it became clear that Phase 2 isn't just arithmetic — it's calculus foundation:

* *Difference (Δ)* — How much changed?
* *Rate (dh/dt)* — How fast is it changing?
* *Accumulation (∫)* — Total change over time?
* *Threshold crossing* — Did we move between levels?

Health scoring needs derivatives to detect WHEN changes are critical vs normal variation.

=== The CENTER (0) Is What Binary Lacks

Ternary's neutral state (0) represents equilibrium — "within tolerance." Binary has no rest state; everything is on/off. This is why ternary bridges analog and digital:

* Analog has margin of error (wisdom, not weakness)
* Digital has precision (when needed)
* Ternary provides both — CENTER tells systems when to care

=== Normalization Is Multi-Layer

The health system uses three representation layers:

1. *Stored (0-255)* — uint8 storage, neutral at 128
2. *True (-100 to +100)* — signed percentage scale
3. *Normalized* — rounded to base (1, 5, 10, 25, 50)

Conversion must be *lossless within tolerance*. This is "just weight" — measuring faithfully.

=== Independent Interconnected Systems

OmniCode, MillenniumOS, CPI-SI, FaithNet — these are independent systems that interconnect. Phase 2 math must stand on its own while enabling future OmniCode reverse engineering.

*Key insight:* Build properly for eventual expressibility, not just immediate use.

[[what-was-discovered]]
== What Was Discovered

Deeper learnings about mathematical foundation and planning approach.

=== Subtraction Is Convenience

Subtraction doesn't need a separate table — it's `add(a, negate(b))`. The math is cleaner:

* Negation table exists
* Addition table exists
* Subtraction = composition of both

Same principle: build primitives, compose operations.

=== Division Serves Normalization

Division isn't general-purpose — it serves normalization formulas (dividing by known constants). From `health.toml`:

* `StoredToTrue = "(stored - 128) * 100 / 127"`
* Division by 127 is fixed, not arbitrary

=== Spatial/Temporal Need Math First

The spatial.h and temporal.h modules from Phase 1 can't work fully without Phase 2 math. Operations on temporal states require arithmetic. The dependency was always there.

=== Plan-Before-Code Is SI Discipline

This session demonstrated: understanding → plan → implementation. Reading Phase 0 and Phase 1 plans, copying Phase 1 as template, targeted updates section by section.

*Key insight:* The same SI disciplines (template-first, targeted retrieval, grep-not-glob) apply to planning documents, not just code.
