//	Structure: == PLAN-003 | anchor chain | problem | proposed solution | why deferred
//	Elements:  status, architecture proposal

[[plan-003]]
== PLAN-003: Text Buffer Architecture

*Status:* Not started (deferred)

*Anchor Chain:*
----
Genesis 1:1 -> Kingdom Technology -> OmniCode -> Text Editor -> Text Buffer
----

*Purpose:* Transform monolithic `pkg/textbuffer/` into modular, config-driven system.

=== The Problem

* `cursor.go` and `undo.go` directly access private fields
* Constants hardcoded (defaultGapSize=256, minGapSize=64)
* No configuration layer
* Tightly coupled — can't swap implementations

=== Proposed Solution

*Config-Driven Architecture:*

[source,go]
----
type TextBufferConfig struct {
    Buffer BufferConfig `toml:"buffer"`
    Cursor CursorConfig `toml:"cursor"`
    Undo   UndoConfig   `toml:"undo"`
}
----

*Interface-Based Separation:*

[source,text]
----
text-buffer/
+-- pkg/
    +-- config/       # TextBufferConfig
    +-- buffer/       # Buffer interface + GapBuffer impl
    +-- cursor/       # Cursor operations (takes Buffer interface)
    +-- undo/         # UndoStack + TrackedBuffer
    +-- textbuffer/   # Convenience package combining all
----

=== Why Deferred

This plan relates to OmniCode text editing infrastructure, not the immediate substrate wiring work. It will become relevant when building the OmniCode IDE/editor.
