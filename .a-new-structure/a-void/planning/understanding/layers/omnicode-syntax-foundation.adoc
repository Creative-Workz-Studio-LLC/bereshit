[[overview]]
== Overview

This document captures the foundational insight for OmniCode syntax: that sentence structure (Subject + Verb + Object) is the universal representation from which all programming syntax derives. OmniCode doesn't pick a syntax style—it IS the meaning that transpiles to any target language.

[IMPORTANT]
====
*#OmniCode is not another programming language.#* It is the universal meaning representation. All syntax styles (C, Lisp, Python, Assembly) are renderings of the same underlying concepts. OmniCode captures the concepts; transpilation produces the syntax.
====

[[the-insight]]
== The Core Insight

**Omni** = all, universal, everything.

OmniCode doesn't pick a syntax style. It #IS the universal representation# from which all syntax styles derive.

All programming languages—from machine code to natural language—express the *same underlying concepts*. The syntax differs, but the meaning is universal. OmniCode captures the meaning; transpilationfootnote:[Transpilation: Source-to-source compilation, translating one language to another at the same abstraction level] produces the syntax for any target.

[cols="2,4",options="header"]
|===
| Universal Concept | How It Manifests in Any Language

| *Identity*
| Variables, names, symbols — every language names things

| *Values*
| Data — numbers, text, collections — every language holds data

| *Operations*
| Transform data — `+`, `add()`, `(+ a b)` — same meaning, different rendering

| *Flow*
| Conditionals, loops, jumps — every language directs execution

| *Structure*
| Blocks, modules, classes — every language organizes

| *Types*
| Categories of data — explicit or inferred, all have them

| *Relationships*
| How things connect — references, ownership, inheritance
|===

[[syntax-levels]]
== The Seven Syntax Levels

Building UP from machine code to natural language, each level adds more *natural language characteristics*:

[cols="^1,2,3,3",options="header"]
|===
| Level | Name | What It Adds | Linguistic Element

| 0
| *Machine*
| Raw binary data
| —

| 1
| *Assembly*
| Instructions
| *Verbs* — MOV, ADD, JMP are actions

| 2
| *Low-level* (C, Rust, Go)
| Named things
| *Nouns* — variables, types

| 3
| *OOP* (Java, C#)
| Things that act
| *Subjects* — objects with methods

| 4
| *Scripting* (Python, JS)
| Readable flow
| *Flow* — less ceremony, more natural sequence

| 5
| *Functional* (Haskell, Lisp)
| Composition
| *Sentences that build* — functions compose

| 6
| *Declarative* (SQL, HTML)
| Intent
| *What you want* — not how

| 7
| *Natural-ish* (COBOL, AppleScript)
| Grammar
| *English-like sentence structure*
|===

=== Syntax Dimensions

Each level makes choices across these dimensions:

[cols="2,4",options="header"]
|===
| Dimension | Styles

| *Block delimiters*
| `{}` braces, indentation, `end` keyword, parentheses

| *Statement termination*
| `;` semicolons, newlines, `.` periods

| *Type position*
| Before name (C), after name (Go/Rust), inferred (Python)

| *Function calls*
| `f(x)` parens, `f x` juxtaposition (Haskell), `(f x)` prefix (Lisp)

| *Operators*
| Infix `a + b`, prefix `(+ a b)`, method `.add()`

| *Comments*
| `//`, `#`, `--`, `;`, `/* */`, `""" """`
|===

//	How Subject-Verb-Object maps to code constructs

[[sentence-structure]]
== Sentence Structure as Universal Grammar

At the top—plain English—we have *universal grammar*:

----
Subject + Verb + Object + Modifiers
----

[quote, Genesis 1:1 KJV]
____
God created the heavens and the earth.
____

* *Subject:* God
* *Verb:* created
* *Object:* heavens, earth

This maps *directly* to code concepts:

[cols="2,4",options="header"]
|===
| Grammar Element | Code Concept

| *Subject*
| Caller, namespace, context — WHO/WHAT acts

| *Verb*
| Operation, function, method — the ACTION

| *Object*
| Parameters, arguments — WHAT'S acted upon

| *Modifiers*
| Options, conditions, types — HOW, WHEN, WHERE
|===

=== The Transpilation

The same meaning renders to any syntax:

[source]
----
OmniCode:  God create heavens, earth
              ↓ transpiles to ↓
C:         create(heavens, earth);        // in God context
OOP:       God.create(heavens, earth);
Lisp:      (God/create heavens earth)
Assembly:  CALL God_create / MOV params...
English:   "God creates the heavens and the earth"
----

*The sentence structure IS the universal representation.*

// # T.5 Native Documentation Syntax [NATIVE-DOCS]
//
//	Documentation IN the language, not alongside it

[[native-documentation]]
== Native Documentation Syntax

[IMPORTANT]
====
*Key insight from alignment work:* OmniCode uses *native syntax* for documentation — documentation lives IN the language, not alongside it in comments.
====

=== The Principle

Traditional languages separate code from documentation:

[source]
----
// This is a comment - separate from the code
function add(a, b) { ... }
----

OmniCode makes documentation part of the syntax:

[source]
----
"name" be word
    meaning "Human-readable name for this folder"
    cautioning "Should be clear and descriptive"
    teaching "Names communicate purpose"
----

=== Native Documentation Keywords

[cols="2,4",options="header"]
|===
| Keyword | Purpose

| *meaning*
| What this element IS — definition, identity

| *teaching*
| How to use it — guidance, examples

| *cautioning*
| What to avoid — warnings, constraints

| *because*
| Why this constraint exists — rationale
|===

=== When to Use Traditional Comments

Traditional comments (`//`, `/* */`) are reserved for:

* *Block boundaries* — `// === METADATA ===`
* *Structural markers* — `// # M.1 Core Identity [IDENTITY]`
* *Template preamble* — Instructions for filling templates

=== Why This Matters

[cols="2,4",options="header"]
|===
| Traditional (Comments) | OmniCode (Native)

| Documentation separate from code
| Documentation IS code

| Easy to get out of sync
| Updates together — single source of truth

| Comments are "for humans only"
| Parseable — tools can extract and verify

| Documentation is optional
| Documentation is structural — part of the declaration
|===

*The language documents itself.* Just as the Bible contains its own explanation (cross-references, concordances), OmniCode contains its own documentation.
