// # C.1 Overview [OVERVIEW]
//
[[overview]]
== Overview

The **void** is the entry gate of the Bereshit filesystem — the formless space where content enters before taking form. Just as Genesis 1:2 describes the earth as "without form, and void" before God spoke form into existence, this directory holds planning, imports, and workflows that await crystallization into the word/ (substance) or tov/ (completion) gates.

=== The Three Gates

[cols="^1,2,3",options="header"]
|===
| Gate | Directory | Role

| **Entry**
| `void/` (a-void/)
| Formless — planning, imports, workflows

| **Substance**
| `word/` (b-word/)
| Formed — definitions, implementations

| **Completion**
| `tov/` (c-tov/)
| Finished — demos, licenses, pricing
|===

// # C.2 Critical [CRITICAL]
//
[IMPORTANT]
====
*Bereshit IS the filesystem root.* The repository models a complete filesystem where void/, word/, and tov/ are the three gates. Content flows: void (formless) → word (formed) → tov (finished).
====

// # T.3 Patterns [PATTERNS]
//
[[patterns]]
== Patterns

Organizational principles governing void/ structure.

=== Three Folder Patterns

[cols="^1,3,3",options="header"]
|===
| Pattern | Folders | Use Case

| **Lifecycle**
| `active/`, `completed/`, `future/`
| Forward-looking work (plans)

| **Knowledge**
| `design/`, `reference/`, `research/`
| Architecture exploration

| **Reactive**
| `active/`, `completed/`
| Needs-driven work (cornerstone, substrate)
|===

=== When to Use Each

* **Lifecycle** (`active/completed/future/`): Use for explicit forward planning. The `future/` folder holds work that's planned but not started.

* **Knowledge** (`design/reference/research/`): Use for architecture exploration where content matures from research → design → reference.

* **Reactive** (`active/completed/`): Use for work that responds to immediate needs rather than forward planning. No `future/` because work emerges from needs.

=== Void's Formless Nature

The void is formless but not structureless. The structure serves the planning/intake function without constraining what can enter:

* **imports/** stays empty until content arrives — let content dictate structure
* **vision/** stays flat — north star remains simple
* **baton-pass-stage/** is explicit transition — content graduates OUT of void
