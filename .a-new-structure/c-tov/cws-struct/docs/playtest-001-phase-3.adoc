== What This Phase Tests

*The same transform, richer understanding.* Phase 1 proved the transform
engine works. Phase 2 upgraded the schema with 5 new concepts (11 → 16),
bidirectional detect+emit+mappings for all concepts in both Rust and Go,
and corrected the subtype (library → module->utility). Phase 3 asks:

1. Does re-transforming a clean file produce zero changes? (Idempotency)
2. What does the upgraded verbose output reveal?
3. Does concept detection work with the new schema?
4. Where does the detection ceiling show up?

=== The Game Dev Parallel

This is a *regression test disguised as a patch note readthrough*. We
shipped the balance patch (Phase 2), now we load the same save file and
see if the new scoring system evaluates it correctly. The character
(graph.rs) didn't respec — the evaluation rubric got smarter. We're
checking that the smarter rubric doesn't break anything AND that it sees
things the old rubric couldn't.

== Step 3: The Detection Ceiling in Action

=== The Recursion Gap

`CWS-R05-071` reports: _Expected concept "recursion" not found in
"free-functions"_

But `has_cycle` IS recursive:

[source,rust]
----
fn has_cycle(
    spec: &str,
    graph: &BTreeMap<String, DependencyNode>,
    visited: &mut BTreeSet<String>,
    in_stack: &mut BTreeSet<String>,
) -> bool {
    // ...
    if let Some(node) = graph.get(spec) {
        for dep in &node.depends_on {
            if has_cycle(dep, graph, visited, in_stack) {  // ← RECURSION
                return true;
            }
        }
    }
    // ...
}
----

Line 223: `has_cycle` calls itself. This is textbook recursion. The schema
grants recursion in free-functions. The code exhibits recursion. But the
detector doesn't see it.

=== Why the Detector Misses It

The recursion regex at R[5] requires knowing two things simultaneously:

1. *What function am I inside?* — Parse the `fn` declaration for the name
2. *Does that name appear as a call in the body?* — Match the name as a
   callee

This is scope-aware analysis — the R[3] layer. A single regex matching
one line at a time cannot relate the function declaration on line 205 to
the call site on line 223. It would need to:

- Track function boundaries (which `fn` block am I in?)
- Remember the function name
- Check if that name appears as a call within the same block

This is exactly the same pattern as the self_access detection ceiling
documented in the <<related,Phase 2 Detection Ceiling journal>>. Both
require scope tracking that regex can't provide.

=== What This Tells Us

[cols="1,2,2", options="header"]
|===
| Detection Layer | What It Can See | What It Can't

| R[5] (current)
| Individual line patterns: `fn`, `let`, `if`, `for`, `match`,
  `self.field`, `pkg::func()`
| Cross-line relationships: "this call references the enclosing function"

| R[3] (next)
| Function scope: "I'm inside `has_cycle`, and `has_cycle()` appears at
  line 223 — that's recursion"
| Type identity: "this variable is a `BTreeMap<String, DependencyNode>`"

| R[2] (future)
| Type awareness: "this method call returns `Option<&DependencyNode>`"
| Cross-file: "this function is called from `loader.rs`"
|===

*The upgraded schema surfaces the gap.* Before Phase 2, the linter had no
concept of "recursion" — it couldn't even ask the question. Now it asks,
gets silence as an answer, and reports it. The schema upgrade didn't
just add scoring — it added *diagnostic visibility*.

== Observations

=== What Phase 3 Proves

[cols="1,2", options="header"]
|===
| Finding | Significance

| *Transform is idempotent*
| Re-transforming a clean file produces zero changes. The engine is
  non-destructive. Safe to re-run at any time.

| *Schema upgrades don't break existing files*
| 100/±100 holds through the concept expansion (11 → 16). The
  scoring system gracefully integrates new knowledge.

| *The recursion detection gap is real*
| R[5] regex cannot detect recursion because it requires scope tracking.
  This is the second confirmed R[3]-layer gap (after self_access in Go).

| *Schema upgrades add diagnostic visibility*
| The old schema couldn't even ask "is there recursion?" Now it asks,
  gets silence, and reports it. The question itself is valuable.

| *Verbose QoL works as designed*
| `--verbose` shows file anatomy. `--deep` shows individual actions.
  Both features confirmed operational in live playtest.
|===

=== The Recursion Pattern (Future R[3] Work)

Two detection gaps now confirmed at the R[5] ceiling:

[cols="1,2,2", options="header"]
|===
| Gap | Language | What R[3] Needs

| self_access
| Go
| Parse function signature to extract receiver parameter name. Track
  receiver binding through function scope.

| recursion
| Rust (and Go)
| Parse `fn` declaration to extract function name. Track whether that
  name appears as a callee within the function body.
|===

Both require the same infrastructure: *function-scope tracking*. Build
one, get the other nearly free. This is the natural next floor of the
detection hierarchy.
