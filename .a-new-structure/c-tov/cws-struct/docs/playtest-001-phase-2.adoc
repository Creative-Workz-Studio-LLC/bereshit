== What This Phase Tests

*The schema must know what it's measuring.* Phase 1 proved the
transform engine works — 171 → 377 lines, -9 → 98, zero manual edits.
But the remaining 2-point gap reveals a schema limitation: the
`library` subtype expects patterns that graph.rs doesn't have because
graph.rs isn't a library.

This phase tests:

1. Do new concepts accurately describe what graph.rs does?
2. Does the correct subtype/typing eliminate false warnings?
3. Does the score reach 100 when the schema matches reality?
4. Does the schema change affect other files negatively?

=== The Game Dev Parallel

This is a *balance patch*. Phase 1 was the content release (the tool
works). Phase 2 is the tuning pass — the scoring system needs
recalibration so it measures the right things for the right file types.

In game design: you built a great RPG class system, but the "Mage"
evaluation criteria are being applied to a "Ranger." The Ranger scores
98 because they're missing "spell slots" that Rangers never had. Fix
the class assignment, fix the evaluation rubric. The player didn't
change — the system's understanding of the player changed.

=== New Atomic Concepts (Irreducible)

5 new patterns that cannot be decomposed into existing concepts:

[cols="1,3,2", options="header"]
|===
| Concept | Definition | Why Atomic (Not Composite)

| *loop_iteration*
| for/while/loop — repetition over collections or conditions
| Not conditional_if (repetition ≠ branching). Not
  function_call (control flow construct, not invocation).
  Unique: only pattern that produces bounded repetition.

| *collection_mutation*
| .insert/.push/.remove/.pop — mutating collection state
| Semantically distinct from method_call: invocation vs
  mutation. Determines if section is pure or stateful.
  A `queries` section should have method_call but NOT
  collection_mutation.

| *type_construction*
| Struct \{ field: value \} — constructing type instances
| Not function_call (no function invoked — literal syntax).
  Not variable_binding (naming vs value-building). The
  "create a structured value" atom.

| *field_access*
| struct.field — reading a property from a structure
| Not method_call (no parens, no behavior invoked). Not
  variable_binding (no new binding created). The "read
  from structure" atom. Read counterpart to
  type_construction (write).

| *recursion*
| Function calling itself — self-targeting invocation
| Composites function_call + self-reference, but like
  self_access composites method_call + self-reference,
  recursion is a distinct behavioral property worth
  tracking. Determines algorithm complexity class.
|===

=== Composite Patterns (Absorbed by Existing + New Atoms)

[cols="1,2,2", options="header"]
|===
| Pattern Found | Composites Into | Why Not Atomic

| early_exit (break/continue)
| loop_iteration + conditional_if
| Can only break from a loop, always conditional

| guard_clause (if x { return })
| conditional_if + return_value
| Early return is a conditional return

| option_unwrap (if let Some)
| conditional_if + variable_binding
| In Go: `v, ok := ...; if ok` = conditional_if +
  variable_binding. Rust sugar doesn't change the atoms.

| destructuring_bind (for (k,v) in)
| variable_binding
| At lowest point, destructuring IS binding with a pattern

| closure_lambda (\|e\| expr)
| (only in test assertions, not domain code)
| Test infrastructure; not a graph.rs domain pattern

| iterator_chain (.iter().any())
| method_call + loop_iteration
| Method produces sequence, loop consumes
|===

== Step 2: Determine Correct Subtype for graph.rs

=== The Decision

[cols="1,2,2", options="header"]
|===
| Option | Pros | Cons

| Keep `library`
| No pragma change
| 9 false warnings, wrong evaluation standard

| Change to `module`
| Correct base type
| Still gets full module expectations

| Change to `module->utility`
| Exact match — stateless free functions, SETUP: Imports only,
  BODY: FreeFunctions only, concept overrides defer most patterns
| Requires pragma change (2 lines in file)
|===

*Decision:* `module->utility`. This is exactly what graph.rs is.

=== What `->utility` Gives Us

From the module typing_map:

----
->utility: "Stateless free functions (exists.rs, paths.rs)"
  SETUP Required: Imports
  BODY Required: FreeFunctions
  Concept overrides (FreeFunctions):
    variable_binding: defer
    conditional_if: defer
    conditional_match: defer
    error_propagation: defer
    err_wrap: defer
    ok_wrap: defer
    string_format: defer
----

Every false warning from Phase 1 would be eliminated:

- No more "missing Constants" — not required for utility
- No more "missing Core Types" — not required for utility
- No more "missing Trait Implementations" — not required for utility
- No more "missing Constructors" — not required for utility
- Concept expectations relaxed to match reality

=== New Concept Overrides for ->utility

The 3 new concepts need overrides in the ->utility typing:

----
loop_iteration: defer
collection_mutation: defer
type_construction: defer
----

A utility module may or may not have these patterns. "defer" means
"don't penalize for presence or absence."
