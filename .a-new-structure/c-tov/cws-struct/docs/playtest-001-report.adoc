=== Playtest 001 — Phase Summary

==== Phase 1: Pragma + Transform

*Subject:* graph.rs (169 lines, directives but no block markers)

*Actions:*

. Added shebang pragma: `// #!omni code --rust -library`
. Ran `deno task transform:rust graph.rs`
. Observed structural scaffold generation

*Results:*

[cols="1,1,1", options="header"]
|===
| Metric | Before | After

| Lines | 171 | 377
| Health | -9/±100 | 98/±100
| Errors | 4 | 0
| Identity fields | 0 | 43
| Blocks | 0 | 4
|===

*Key finding:* The transform engine builds complete 4-block structure from a
single pragma line. Zero manual edits required. The 2-point gap came from a
subtype mismatch (schema expected library patterns on a module file).

*Status:* link:playtest-001-phase-1.adoc[Complete]

==== Phase 2: Schema Upgrade

*Subject:* Schema definitions (not graph.rs itself)

*Actions:*

. Created 5 new concept schemas (16 total)
. Added bidirectional detect+emit+mappings to all concepts (22 schema files)
. Changed graph.rs subtype from `library` to `module->utility`

*Results:*

[cols="1,1,1", options="header"]
|===
| Metric | Before | After

| Health | 98/±100 | 100/±100
| Concepts in schema | 11 | 16
| Schema files upgraded | 0 | 22
| File modifications | — | 0 (schema only)
|===

*Key finding:* The 2-point gap closed by correcting the schema, not the file.
The file was correct — the standard was wrong. This is the "just weight"
principle: the measuring instrument must be accurate before judging the
measured.

*Status:* link:playtest-001-phase-2.adoc[Complete]

==== Phase 3: Re-Transform

*Subject:* graph.rs (re-transform with upgraded schema)

*Actions:*

. Backed up Phase 1 result
. Re-ran `deno task transform:rust graph.rs` with the 16-concept schema
. Diffed against Phase 1 output

*Results:*

[cols="1,2", options="header"]
|===
| Metric | Value

| Diff
| Zero — idempotent transform

| Health
| 100/±100 (unchanged)

| New detections
| 0 (concept detection requires code pattern matching not yet implemented)
|===

*Key finding:* Transform idempotency proven. Running the same transform twice
produces identical output. The schema upgrade affected scoring, not
transformation.

*Status:* link:playtest-001-phase-3.adoc[Complete]

==== Phase 4: Transpile (Not Executed)

*Designed:* Transpile graph.rs Rust → Go, verify structural fidelity.

*Status:* Deferred. The transpiler was verified independently against exists.rs
(543 lines Go output, 43/43 identity fields, 8/8 function bodies). graph.rs
transpilation was deprioritized in favor of the engine upgrade.

==== Phase 5: Apply to cache.rs (Not Executed)

*Designed:* Full pipeline (pragma → transform → lint) on cache.rs.

*Status:* Deferred. cache.rs remains the untouched subject for Playtest 002.

== Part IV: Playtest 002 — Design Brief

=== The Core Question

*Does the scoring system tell the truth across ALL formats?*

Playtest 001 tested Rust only. Playtest 002 should exercise the full format
range: Go, TOML, JSON, Makefile, Dotfiles, and OmniCode. The bridge function
(`computeHealthFromResults`) is new infrastructure — does it produce meaningful
scores that guide the user toward alignment?

=== Proposed Subjects

[cols="2,1,2,2", options="header"]
|===
| File | Format | Why This File | Expected Challenge

| cache.rs
| Rust
| Deferred from PT001 — untouched subject, no pragma
| Pragma → transform → score arc on a fresh file

| A production Go file
| Go
| Go handler is heavy (inspect, transform, create, health) — untested live
| Full pipeline should work; verify Go-specific schema

| A real Makefile (e.g. cws-struct root)
| Makefile
| Bridge function for Makefile — first live scoring
| Does the bridge produce meaningful scores?

| A real .editorconfig
| Dotfiles
| Simplest handler — is the bridge honest when most checks pass?
| Baseline: should score high on a well-formed dotfile

| A TOML schema file
| TOML
| TOML handler is heavy (113 checks) — verify depth
| Schema files should score 100; deviations reveal schema drift

| A .omni file
| OmniCode
| OmniCode is our format — we should eat our own cooking
| Does OmniCode lint + transform + score tell the truth?
|===

=== Phases

==== Phase 1: Multi-Format Baseline

Lint one file from each format. Record scores, error counts, action
counts. The question: *do the numbers make sense?*

Expected outcomes:

* Well-formed files (editorconfig, Makefile) should score 80+
* Files with pragma (exists.rs, aligned Go) should score 100
* Files without pragma should score via lenient module fallback
* The bridge function should produce differentiated scores (not all-100)

==== Phase 2: Fresh Transform (cache.rs)

Run the full pragma → transform → score pipeline on cache.rs.

Expected outcomes:

* Health drops when pragma is added (covenant declaration)
* Transform scaffolds structure (similar to graph.rs: 170 → 370+ lines)
* Post-transform score reaches 95+
* Any gap reveals schema or subtype issues (like Phase 2 of PT001)

==== Phase 3: Go Full Pipeline

Pick a production Go file, run lint → transform → transpile → lint.

Expected outcomes:

* Go lint matches Rust lint in depth (both heavy handlers)
* Transform adds structure without destroying existing code
* Transpile Go → Rust produces valid Rust structure
* Round-trip: Go → Rust → Go preserves identity (this is ambitious)

==== Phase 4: Bridge Function Audit

Run verbose + deep on files scored by the bridge function (JSON, Makefile,
Dotfiles, Omni, OFD). Compare the breakdown against manual inspection.

Expected outcomes:

* Bridge scores should correlate with actual file quality
* Container groupings should be meaningful (not all "general")
* Passing check inference should be reasonable
* Scores on well-formed files should be high (85+)
* Scores on broken files should be low (<50)

==== Phase 5: Verbose Output QoL (If Time)

The verbose output plan (link:../word/claude/plans/sparkling-spinning-starfish.md[plan]) calls for:

* Directives section (what the linter sees as identity)
* Blocks section (line ranges, sizes)
* Identity section (all resolved fields with values)
* Per-action detail within health breakdown (`--deep`)

If the verbose upgrade lands before PT002, test it across all formats.

=== Success Criteria

[cols="1,2", options="header"]
|===
| Criterion | How to Verify

| Multi-format scoring accuracy
| Manual inspection of 6+ files confirms scores are honest

| Bridge function produces meaningful differentiation
| Not all scores are 100; broken files score lower than clean ones

| Full pipeline works on Go
| Lint → transform → transpile → lint produces consistent results

| cache.rs aligns in one session
| Pragma → transform → score ≥ 95 without manual intervention

| No regressions
| `deno task test` — 1709+ passed, 0 failed
|===
