= L2 Platform

== Purpose

Platform services layer — the firmament between foundation and application.
Filesystem contracts, health monitoring, terminal utilities, server configuration,
permission models, and (future) database platform services.

== Structure

----
L2-platform/
├── ladder/                         ← Specs (TOML contracts)
│   ├── filesystem/                 ← Filesystem contract + types
│   ├── os/                         ← OS services
│   │   ├── health/                 ← Health monitoring (6 specs)
│   │   └── permission/             ← Permission model
│   └── database/                   ← Platform database contract (upcoming)
├── hybrid/                         ← Code (Go — platform services)
│   ├── server/                     ← Server config + services
│   │   ├── config/                 ← Hosts, paths, preferences, server
│   │   └── services/builder/       ← Builder service handler
│   ├── util/                       ← Utilities
│   │   ├── term/                   ← Terminal (display, system, temporal, debug, wezterm)
│   │   └── vcs/git/                ← Git operations
│   ├── drivers/                    ← Hardware abstraction (placeholder)
│   ├── fuse/                       ← FUSE bridge layer (placeholder)
│   ├── millenniumos/               ← MillenniumOS (placeholder)
│   └── substrates/                 ← Substrate-specific platform code
│       └── millenniumos/           ← MillenniumOS substrate (placeholder)
├── spiral/                         ← Future (Rust crates)
└── root.adoc                       ← This file
----

== Build

 make -C L2-platform check

Runs quality gate: Go vet, structural lint, tests.
