= Placement Layer (R[10]) — Content-Kind Mapping

[quote, 1 Corinthians 14:40]
____
Let all things be done decently and in order.
____

== Overview

The placement layer answers one question: *is this construct in the right place?*

It sits at R[10] detection granularity — between structural organization (R[25]) and content substance (R[5]).
Where R[25] checks that blocks and sections _exist_ and are _ordered_, placement checks that the right _constructs_ live in the right _blocks_ and _subsections_.

== What Placement Maps

Each format has a content-kinds file that maps source-level construct categories to structural locations.

=== Three Map Types

block_placement:: Which block does this construct belong in? (SETUP vs BODY)
subsection_placement:: Which subsection within a block? (Imports, Constants, CoreTypes, etc.)
metadata_forbidden:: Which constructs must NOT appear in METADATA?

=== Format Files

[cols="1,3"]
|===
| Path | Description

| `rust/content-kinds.jsonc`
| 12 Rust content kinds -> 2 blocks, 8 subsections

| `go/content-kinds.jsonc`
| 7 Go content kinds -> 2 blocks, 5 subsections
|===

== The Principle

Without placement, you could have a structurally valid file with everything in the wrong block.
A `struct` in BODY. A `fn` in SETUP. A `use` in METADATA.
All blocks present and ordered — but the code is in chaos.

Placement is the rule that says: *declarations in SETUP, logic in BODY, comments in METADATA.*

The construct tells you what it is. The placement map tells you where it goes.
Identity determines structure.
