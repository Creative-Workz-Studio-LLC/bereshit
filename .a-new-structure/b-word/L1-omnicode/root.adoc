= L1 OmniCode

== Purpose

The OmniCode programming language — sentence-like syntax where the Bible
serves as the codex. Defines keyword vocabulary, syntax rules, file extension
registry, pragma parsing, format dispatch, and block structure schemas.
All built on L0's universal foundation.

== Execution Modes

[cols="1,2,3"]
|===
| Mode | Characteristic | Contents

| *Ladder*
| Strict sequence. Spec precedes implementation. Definitions precede runtime.
| TOML specs (syntax, keywords, extensions, operators), JSONC schemas

| *Spiral*
| Iterative. Self-awareness grows as the language matures.
| Identity scaffold (future: L1 describes itself in OmniCode)

| *Hybrid*
| Ladder forward, spiral to recover. Parser dispatches, recovers on error.
| Pragma reader (Go), compiler pipeline stubs (codegen, IR, VM, semantic)
|===

== Design

Ladder provides the truth — TOML specs define what OmniCode IS. The schemas
define what valid block structure looks like. These are the law.

Hybrid reads that truth at runtime — the pragma reader parses `#!omni` lines
from any file format, the dispatcher routes to the right L0 parser, and the
extension registry maps file extensions to their OmniCode identity.

Spiral will grow — when the language can describe itself (OmniCode written
in OmniCode), the spiral domain comes alive. The seed of self-awareness is
already planted: the pragma reader can parse its own pragma lines.

The three domains mirror L0's fractal pattern. Each layer of the stack carries
the same three natures: sequential truth (ladder), self-knowing identity
(spiral), and ordered execution with recovery (hybrid).
