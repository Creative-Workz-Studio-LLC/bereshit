= L0 Universal

== Purpose

Universal foundations that every layer above depends on. Organized by
execution mode — ladder (strict order), spiral (iterative), hybrid (both).

== Execution Modes

[cols="1,2,3"]
|===
| Mode | Characteristic | Contents

| *Ladder*
| Strict sequence. Can't skip, can't reorder. Baton passes forward only.
| TOML specs (bible → math → types), C libraries (libtrit, libmath)

| *Spiral*
| Iterative. Revisits, grows, never done.
| Identity registry (instances register/evolve), glossary definitions

| *Hybrid*
| Ladder forward, spiral to recover. Ordered execution with fallback loops.
| Config loader, path resolution, CLI scaffolding, display formatting
|===

== Design

Identity registry (spiral) is the bootstrap anchor — it registers itself, then
every other package registers at `init()` time. The system knows itself at runtime.

Config loader (hybrid) dispatches by file extension (TOML, JSONC) and loads
foundation specs (ladder) in manifest order with fallback/retry for recovery.

Domain packages (hybrid/{paths,cli,format,output}) are pure stdlib + L0 identity.
No package in L0 imports from L1 or above. The layer boundary is a compile-time
guarantee. Each domain is a genuine architectural seam — independently replaceable.

Scaffold directories (ladder/libtrit, ladder/libmath, spiral/definitions) are
staging areas for content migrating from older locations. They contain `.gitkeep`
files and will be populated as migration continues.
