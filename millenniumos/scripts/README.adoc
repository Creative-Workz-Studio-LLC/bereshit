This directory contains all build, run, and configuration scripts for MillenniumOS.
The system is *config-driven* and *data-driven* — configuration files define behavior,
scripts execute based on that configuration.

== Overview

[cols="1,3"]
|===
|Component |Purpose

|`run.sh`
|Main launcher — orchestrates build and QEMU execution

|`qemu/`
|QEMU virtual machine scripts organized by boot mode

|`qemu/config/`
|Configuration files driving all QEMU behavior
|===

== Directory Structure

[source]
----
scripts/
├── README.adoc              # This documentation
├── run.sh                   # Main launcher (config-driven orchestrator)
│
└── qemu/                    # QEMU-specific configurations
    ├── README.adoc          # QEMU scripts documentation
    │
    ├── uefi/                # UEFI boot scripts
    │   ├── run-uefi.sh          # Primary EDK2-compatible boot
    │   ├── run-uefi-simple.sh   # QEMU vvfat fallback
    │   └── run-uefi-debug.sh    # Debug mode with GDB
    │
    ├── bios/                # Legacy BIOS boot scripts
    │   └── run-bios.sh          # SeaBIOS/legacy boot
    │
    └── config/              # Configuration files
        └── uefi.cfg             # UEFI/QEMU configuration
----

== Main Launcher (run.sh)

The main launcher is a *config-driven orchestrator* that:

* Loads configuration from `qemu/config/uefi.cfg`
* Checks build requirements
* Delegates to dedicated QEMU scripts
* Provides status, logging, and help

=== Commands

[cols="1,3"]
|===
|Command |Description

|`(default)`
|Build if needed, run in UEFI mode

|`build`
|Build MillenniumOS

|`run`
|Run in QEMU (requires built image)

|`clean`
|Clean build artifacts

|`rebuild`
|Clean and rebuild

|`status`
|Show build status and configuration

|`check`
|Check tool requirements

|`logs`
|View debug logs

|`help`
|Show help with architecture diagram
|===

=== Boot Modes

[cols="1,3"]
|===
|Option |Description

|`--uefi`
|UEFI mode with GOP graphics (default, modern)

|`--bios`
|BIOS mode with VESA graphics (legacy fallback)
|===

=== Debug Options

[cols="1,3"]
|===
|Option |Description

|`--debug`
|Enable debug output

|`--gdb`
|Start GDB server on :1234

|`--verbose`
|Verbose build output (make V=1)
|===

=== Examples

[source,bash]
----
# Build and run (UEFI mode)
./scripts/run.sh

# Build and run in BIOS mode
./scripts/run.sh --bios

# Just build
./scripts/run.sh build

# Check build status and configuration
./scripts/run.sh status

# Check tool requirements
./scripts/run.sh check

# View debug logs
./scripts/run.sh logs

# Rebuild from scratch
./scripts/run.sh rebuild

# Run with verbose build
./scripts/run.sh --verbose build
----

== Configuration System

The scripts use a *config-driven* approach. All QEMU settings are defined in
`qemu/config/uefi.cfg` and sourced by the scripts.

=== Configuration Sections

[cols="1,3"]
|===
|Section |Contents

|Machine Configuration
|QEMU machine type, CPU, SMP, memory

|Firmware Configuration
|OVMF/EDK2 paths (system and custom)

|Storage Configuration
|ESP size, partition settings, controller type

|Display Configuration
|VGA type, display backend, GOP defaults

|Serial Port Configuration
|COM1/COM2 ports, IRQs, output files

|Debug Configuration
|GDB settings, QEMU debug flags

|Network Configuration
|Network settings (future)

|Audio Configuration
|Audio settings (future)

|USB Configuration
|USB controller settings

|Boot Configuration
|Boot order, startup.nsh content

|Visual Debug Colors
|Framebuffer debug color codes

|Kingdom Technology Branding
|OS name, version, copyright, tagline, scripture
|===

=== Key Configuration Values

[source,bash]
----
# Machine
QEMU_MACHINE="q35"
QEMU_CPU="qemu64"
QEMU_MEMORY="512M"

# Branding
OS_NAME="MillenniumOS"
OS_VERSION="a-01.00"
OS_TAGLINE="Redeeming Technology for the Kingdom"
OS_SCRIPTURE="In the beginning God created the heaven and the earth. — Genesis 1:1"
----

== Boot Architecture

[source]
----
┌─────────────────────────────────────────────────────────────┐
│                      MillenniumOS                           │
│           Kingdom Technology Operating System               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   UEFI Boot (Primary)        │   BIOS Boot (Fallback)      │
│   ├─ BOOTX64.EFI             │   ├─ Stage 0a (MBR)         │
│   ├─ GOP Framebuffer         │   ├─ Stage 0b (Loader)      │
│   └─ kernel.bin              │   └─ kernel.bin             │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                        Kernel                               │
│   ├─ entry.asm (64-bit entry point)                        │
│   ├─ kernel.c (kernel main)                                │
│   ├─ DAR Witness System (logging)                          │
│   └─ Subsystems (memory, interrupts, timer, scheduler)     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
----

== Script Structure

All scripts follow the *4-block structure*:

[source]
----
# METADATA    - Identity, purpose, authorship
# SETUP       - Variables, configuration, imports
# BODY        - Functions organized by section (B.1, B.2, etc.)
# CLOSING     - Main entry point, execution
----

=== run.sh Sections
