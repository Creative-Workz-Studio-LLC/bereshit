== Overview

[sidebar]
.Biblical Foundation
****
[quote, Nehemiah 2:18]
____
"Let us rise up and build. So they strengthened their hands for this good work."
____

One server. Three services. Zero framework dependencies. Built with Go's standard
library because infrastructure should be as reliable as the foundation it stands on.
****

The CWS Server unifies company infrastructure into a single binary:

[cols="1,3,2"]
|===
| Service | Purpose | Route Prefix

| *Builder Dashboard*
| Process execution, build config, editorial tooling
| `/api/builder/*`

| *CPI-SI*
| State machine queries, journal CRUD, FTS5 search
| `/api/cpisi/*`

| *Company Website*
| Static site with host-based routing
| Root domain
|===

=== Key Design Decisions

* *Standard library HTTP* — No Gin, Echo, or Chi. Go 1.22's pattern-based routing
  (`GET /api/builder/commands/run`) is expressive enough without third-party routers.
* *WebSocket via nhooyr.io/websocket* — Process output and CPI-SI state changes
  stream to browser clients in real-time through a fan-in/fan-out hub.
* *Pure Go SQLite* — `modernc.org/sqlite` compiles without CGO, making cross-compilation
  trivial and deployments single-binary.
* *Host-based routing* — The root domain serves the company website; subdomains
  serve the dashboard. One server, multiple sites.
* *Graceful degradation* — Each service initializes independently. If builder can't
  find a project directory, it disables itself without affecting CPI-SI or the website.

== Quick Start

=== Development

[source,bash]
----
# Build and run in dev mode (auto-detects project directory)
make run

# Or specify the project directory
make run BUILDER_DIR=/path/to/company-docs PORT=3847

# Check code compiles (go vet + build)
make check
----

=== Production Deploy

[source,bash]
----
# Full deploy: build → compile TS → sync → restart
make deploy

# Partial deploys (targeted, faster)
make deploy-binary   # Go binary only (restarts service)
make deploy-dash     # Dashboard frontend + config (no restart)
make deploy-site     # Website static files (no restart)
make deploy-builder  # Builder CLI + node_modules
----

=== Production Monitoring

[source,bash]
----
make prod-status     # Health check + version info
make prod-logs       # Tail journalctl
make prod-health     # View watchdog health log
make prod-ssh        # SSH into Dell server
----

== Architecture

=== Service Composition

Services are composed in `main.go` at startup:

[source]
----
Flags/Env → Config → Resolve Paths
                         ↓
                    WebSocket Hub ← shared by all services
                         ↓
              ┌──────────┼──────────┐
              ↓          ↓          ↓
          Builder     CPI-SI     Website
         (if paths   (if flag    (if dir
          resolve)    enabled)    exists)
              ↓          ↓          ↓
              └──→ ServeMux ←──────┘
                      ↓
              Middleware Chain
         Recovery → Logger → RequestID
              → CORS → SecurityHeaders
                      ↓
              HostRouter (if website)
                   or
              ServeMux directly
----

=== Request Flow

[source]
----
HTTP Request
  → Recovery (catch panics)
    → RequestLogger (timing, status capture)
      → RequestID (crypto/rand hex)
        → CORS (permissive for tunnel/dev)
          → SecurityHeaders (nosniff, deny frame, API no-store)
            → HostRouter
              ├─ creativeworkzstudio.com → Website SPA
              ├─ dashboard.* → Builder Dashboard SPA + API
              └─ * (catch-all) → API ServeMux
----

=== WebSocket Protocol

The `/ws` endpoint provides real-time streaming. Messages are JSON with a `type` field:

[cols="1,1,3"]
|===
| Type | Source | Description

| `output`
| Builder
| Process stdout/stderr line (ANSI stripped)

| `exit`
| Builder
| Process completed with exit code

| `state_update`
| CPI-SI
| State machine change from DashboardService
|===
