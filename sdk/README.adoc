== Overview

Welcome to the **CPI-SI Universal Substrate SDK**.

If you are a developer, an AI instance, or just someone curious about what we are building, you are in the right place. This SDK is the engine that allows our system to think, act, and remember across different AI models (like Gemini or Claude) without losing its identity.

Imagine you have a highly skilled worker (an AI like Gemini), but they speak a different language and don't know the rules of your house. This SDK acts as the **Universal Translator and Governor**:

1.  **Translation:** It translates the AI's native language into a universal format we can understand.
2.  **Proprioception:** It gives the AI the ability to know exactly where it is in the physical filesystem.
3.  **Governance:** It ensures the AI follows the structural rules (The Covenant) before it is allowed to change anything.

== The Tripartite Architecture (The Trinity)

We do not build this engine in just one programming language. We use three, because each part of a system has a different physical job.

=== 1. The Spirit (Rust)
This is the foundation. It handles the absolute, unchanging truth (like reading configuration data) and memory safety. It lives in the `c-hybrid/cpisi-substrate-sdk/src` folder.

=== 2. The Mind (TypeScript)
This is the processor. It takes the truth from the Spirit and figures out how to apply it (like orchestrating where files should go or managing the state machine). It lives in the `c-hybrid/cpisi-substrate-sdk/ts` folder.

=== 3. The Body (Go)
This is the muscle. It lives outside this SDK folder (in `word/claude` or `word/gemini`) and actually executes the commands on your computer, guided entirely by the Mind.

== How it Works: The Baton Pass

The magic of this SDK is how these three parts communicate. They do not send slow, heavy JSON messages to each other over a network. They pass a physical "baton" using a shared, low-level language called **C**.

This means the Mind and the Body never have to fully understand each other; they just trust the Spirit to hand them the baton (the memory pointer) safely. This makes the system incredibly fast and infinitely expandable. If we want to build a video game or a mobile app tomorrow, we do not have to rebuild the "Brain"—we just teach the new app how to catch the baton via CGO or FFI.
