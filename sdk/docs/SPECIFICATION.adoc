== Introduction

This specification defines the core components of the CPI-SI SDK, focusing on the **Data-Driven Dynamic Structural Algorithm (DSA)**.

== I. Core Components

1.  **DsaRegistry (The Law):**
    *   **Function:** Centralized authority for mathematical and topological constants.
    *   **Data Sources:** `math.toml`, `topology.toml`, `raw_terminal.toml`.
    *   **Fail-safe:** Implements a "Middle-Layer Tripwire" (SEED data) to maintain integrity if filesystem access is lost.

2.  **DsaEngine (The Physics):**
    *   **Function:** Calculates horizontal and vertical tension based on Anchor Scopes.
    *   **Logic:** Implements Outside-In and Inside-Out scaling formulas.
    *   **Health:** Generates "Shalem Reports" to detect structural compression or entropy.

3.  **VaultDrawer (The Manifestation):**
    *   **Function:** Renders ASCII Vaults with support for T, L, and Cross joints.
    *   **Features:** Exclusive Door Rule (Exterior-only breathing), 242-char Double Witness support, and Style-aware glyphs (Normal, Sink, Popout).

4.  **CwsTestRunner (The Validation):**
    *   **Function:** Automated geometric and structural validation.
    *   **Reporting:** Renders validation results within standardized ASCII Vaults.

== II. Data Schema

The SDK is governed by a TOML-based schema:
*   `u`: Universal Structural Unit (Integer).
*   `n`: Bible Factor (Integer).
*   `witness`: Scaling factors ($121, 242, 484$).
*   `joints`: Mapping of topological intersections to visual characters.

== III. The Rule of the Pillar

All internal dividers (Spines and Horizons) are **Solid (║)**. Only exterior walls of the Master Root are permitted to open as "Doors" for code content. This ensures the structural backbone of the file remains immovable.

== IV. Compliance Levels

*   **Shalem (100%):** Zero violations. Perfect 3:2:1 ratio.
*   **Chata (<100%):** Deviation detected. Compression or entropy present.
