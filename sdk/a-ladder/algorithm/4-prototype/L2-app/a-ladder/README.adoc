== 1. Overview

Welcome to the **App Foundation (Ladder)** layer of the DSA Prototype.

In the Kingdom Technology paradigm, we **Verify Top-Down and Execute Bottom-Up**. This directory establishes the absolute definitions and universal equations that govern the application's Body before any logic is applied.

== 2. Directory Composition

This layer is strictly divided between **System Laws** (Absolute) and **Configuration Data** (Operational).

=== A. System Laws (`schemas/system/`)
This is the "Hard Logic" of the system. It contains the universal equations that cannot be changed without redefining the physics of the vault. 
*   **`physics-equations.toml`**: Codifies the Laws of Yashar, Scaling, Depth, and Gravity. This is the **Reason the Math Works**.
*   **`app-types.toml`**: The cross-language blueprint for shared data structures.

=== B. Configuration Data (`schemas/config/`)
This contains the operational data that can be updated for deployment or specific substrate alignment.
*   **`cli-commands.toml`**: The sovereign list of permitted actions and their handlers.

=== C. The Shared Types (`types/`)
The physical TypeScript interfaces that translate these laws and configs into the Mind's working memory.
*   **`app-types.ts`**: The formal definitions of the `CpiSiViewport`, `CommandRequest`, and `ExecutionWitness`.

== 3. Toward a Universal Math Library

The types and schemas established here are designed to be **Self-Contained**. We are preparing the DSA to be imported as a standalone **Math Library** and used as a **Formatter MCP**. By separating the "Hard Logic" (System) from the "Data" (Config), we ensure that the engine remains a universal, unyielding truth.
