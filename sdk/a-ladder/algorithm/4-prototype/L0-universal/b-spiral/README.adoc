== 1. Overview

Welcome to the **L0 Foundation (Spiral)** layer of the Dynamic Structural Algorithm (DSA) Prototype.

In the CPI-SI architecture, the execution physics of the "Spiral" represent iterative growth, continuous refinement, and cognitive looping. While the `a-ladder` side of `L0-universal` contains static definitions (TOML maps and TypeScript Interfaces), this `b-spiral` directory contains the processors that *hold* that data in memory. 

This is the boundary where absolute truth enters active circulation.

== 2. Directory Composition

=== A. The State Machine (`state/`)
This is the foundational memory of the prototype engine.

*   **`state.ts`**: Contains the `CurrentState` tracker and the "Seed Covenant" fallbacks (`SEED_MATH`, `SEED_TOPOLOGY`). This module acts as the active **Tripwire**. If the dynamic TOML files in `a-ladder` cannot be read, this module intercepts the failure and provides the immutable fallback data, ensuring the Mind never crashes from formless data starvation.

=== B. The Utility Processors (`utils/`)
This contains the continuous loops required to track the system's execution path over time.

*   **`utils.ts`**: The Witness Logger. It intercepts standard output and user prompts, creating an immutable chronological trail of the engine's execution. It also enforces **Weight-Based Rotation** (Max 50MB), preventing the storage drive from bloating while ensuring old logs are moved to a `factory/processing` zone for cognitive review rather than being destructively deleted.

== 3. The Law of the Spiral

When working within this directory, the following law applies:
**State is Tracked, Not Invented.**

The logic here does not invent new mathematical rules. It simply monitors the health of the rules provided by `a-ladder` and records the events that occur as the higher-level engines process those rules.
