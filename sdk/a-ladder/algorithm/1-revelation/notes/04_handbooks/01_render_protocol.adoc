== 1. The Exclusive Door Rule

In the physical rendering of the 140-column vault, doors are defined as "Negative Walls" (-1 state). They are the open entry points (`//`) where syntax and language interact with the structured space.

*   **Exterior Only:** ONLY the absolute exterior walls of the Master Root can open as doors.
*   **Solid Interiors:** INTERNAL walls (Spines and Horizons) are ALWAYS solid `║` (+1 state). They cannot be opened, or the vault loses structural integrity.

=== Rendering Protocol
[source,pseudocode]
----
If Code present -> Side.Door = OPEN (//)
If Side is Shared -> Side.Door = FORCE_CLOSED (║)
----

== 2. The Frame Logic (`//`)

The `//` prefix/suffix serves as the structural hinge between the underlying programming language's comment system and the CPI-SI vault geometry.

[horizontal]
**Standard**:: `// [Code] ║` (Open left, solid right)
**Flipped**:: `║ [Code] //` (Solid left, open right)
**Spanned**:: `// [Code] //` (Open on both sides — used rarely for floating anchors)

== 3. Duality Transition (Sign-Flip)

The vault must mathematically maintain zero total tension at all times (Yashar).

[stem]
++++
(\text{Positive Wall}) + (\text{Negative Door}) = 0
++++

To transition a block from a "Normal" (+Z) state to a "Sink" (-Z) state (e.g., when quarantining technical debt), the system applies a Sign-Flip. 

**Execution:**
Flip the heavy structural glyphs (`╔`, `║`, `╚`) to LIGHT (`─`, `│`) or DASHED (`╍`, `╏`) glyphs. This visually lowers the tension, allowing the block to recess into the floor of the vault.
