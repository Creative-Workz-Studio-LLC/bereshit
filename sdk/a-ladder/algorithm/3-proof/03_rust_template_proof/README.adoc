== 3. Examining the Fixture

Open `main_template.rs` and observe how the file is partitioned. This fixture demonstrates a complex multi-witness environment where several structural rules intersect.

=== The T-Joints (Hierarchy and Validation)
Notice how the `[BLOCK:METADATA]` and `[BLOCK:ROOT]` containers span the full 140 columns across the top and bottom of the file. 

*   **The T-Up Joint (`╩`):** Observe where the vertical pillar separating the inner columns hits the bottom of the Metadata block. This proves the **Topology of Governance**. The Metadata roof acts as an absolute covenant governing everything beneath it.
*   **The T-Down Joint (`╦`):** Observe where the inner pillars hit the top of the Closing block. This proves the **Topology of Validation**. The Closing floor acts as a unified terminal expanse; all parallel execution paths must funnel down into this single validation block to exit the file safely.

=== The Internal Spines and The Law of the Pillar
In a multi-witness state, you will notice central dividers separating the left blocks from the right blocks. 

This demonstrates the **Law of the Pillar** and the **Exclusive Door Rule**:
*   The exterior walls of the Master Vault can open (`//`) to let code in.
*   The interior walls (the Spines) are *always* solid (`║` or `│`). They cannot open. They are load-bearing dividers that prevent the logic on the left from bleeding into the logic on the right.

=== The L-Joints (Relational Context)
Observe the intersections between the inner blocks (e.g., `[SETUP]`, `[BODY]`). The physical walls declare the relationship between the domains. An L-Joint (`╠` or `╣`) proves the **Topology of Support**, showing that one block is standing alongside another to provide persistent reference (e.g., keeping a setup configuration visible on the left while multiple body logic blocks execute on the right).
