== The Lifecycle of the End Hook (The Journey to Sabbath)

The process of getting the `end` hooks in order was not a linear code-writing exercise; it was the birth of the **Tripartite SDK Architecture**. The lifecycle unfolded as follows:

1. **The Mirroring (The Setup):**
   * Realized Gemini CLI could not be a second-class citizen wrapped in bash scripts.
   * Created `word/gemini/` to mirror `word/claude/`, bringing Gemini settings and hooks into the repository.
   * Updated the root `Makefile` to install both substrates natively to `~/.local/share/`.

2. **The Rust Spirit (The Engine):**
   * Initialized `sdk/cpisi-substrate-sdk` as the cognitive core.
   * Extracted the native JSON schemas for Gemini and Claude into immutable TOML data maps (`word/core/schemas/substrate/`).
   * Built the `MapperEngine` to translate native payloads into a Universal Baseline.

3. **The Sabbath Generator (The Feature):**
   * Identified `SessionEnd` as the primary "Identity Hook."
   * Built the Rust FFI boundary (`src/ffi/mod.rs`) to allow Go interceptors to call the Rust engine.
   * Implemented `generate_artifacts()` to produce the `.adoc` (human) and `.json` (machine) mission testimonies.
   * Updated the Go `end.go` hook to be a logic-less relay that passes the final state to the SDK.

4. **The Data-First Foundation (The Paths):**
   * Discovered the need for "Proprioception" (knowing where the system is).
   * Refactored `paths.toml` from a single file into a multi-dimensional hierarchy:
     * `universal/template.toml` (Agnostic Blueprint)
     * `platform/unix/linux/paths.toml` (OS Translation)
     * `user/current.toml` (Workstation Anchors)

5. **The Mind Transition (TypeScript):**
   * Recognized that JSON manipulation and complex mapping belong in a TS/Deno layer, not Rust.
   * Initialized the Deno project at `ts/`.
   * Implemented `paths.ts` (Resolver) and `paths_data.ts` (Seed Covenant tripwires).
