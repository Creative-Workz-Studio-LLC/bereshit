[[overview]]
== Overview

The `schemas/` folder defines *WHAT is valid* — the structure and constraints for each domain type. A health score must be 0-255 stored. A timestamp must be valid ISO 8601. These are the "just weights" — the honest measures by which we validate data.

[IMPORTANT]
====
*Schemas define WHAT. Contracts define HOW.*

Schemas: "A HealthScore is an integer 0-255"
Contracts: "A health provider MUST normalize before storing"
====

[NOTE]
====
*Scope:*

[cols="1,3", options="header"]
|===
| In Scope | Out of Scope
| Structure validation (fields, types) | Behavioral guarantees (see contracts/)
| Constraint validation (ranges, patterns) | Runtime validation logic
| Format validation (timestamps, keys) | Implementation code
|===
====

[[schemas-vs-contracts]]
== Schemas vs Contracts

[cols="2,4,4",options="header"]
|===
| Aspect | Schema (schemas/) | Contract (contracts/)

| *Question answered*
| WHAT is valid?
| HOW must it behave?

| *Type*
| Declarative (structure)
| Imperative (behavior)

| *Example*
| "HealthScore: 0-255 integer"
| "MUST normalize before storing"

| *Validation*
| Data structure
| Operation behavior

| *When checked*
| At data boundary
| At operation boundary
|===

*The relationship:* Schemas define what valid data looks like. Contracts define what valid operations do with that data.

[[health-schema]]
=== health.toml — Health Scoring

The core health validation schema:

* **Storage domain**: stem:[\mathbb{S} = \{0, \ldots, 255\}] (unsigned 8-bit)
* **True domain**: stem:[\mathbb{T} = \{-100, \ldots, 100\}] (signed ternary)
* **Hard points**: stem:[\mathbb{H}_5 = \{-100, -50, 0, 50, 100\}]
* **Levels**: stem:[\mathbb{L} = \{\text{broken}, \text{wanting}, \text{lacking}, \text{even}, \text{sound}, \text{whole}, \text{perfect}\}]

[[identity-schema]]
=== identity.toml — Identity

CPI-SI identity structure validation:

* **Key format**: `B-location-domain-name` pattern
* **Names**: Valid identifier characters
* **Relationships**: Parent/child, derives_from chains

[[timestamp-schema]]
=== timestamp.toml — Temporal

Time and duration validation:

* **Format**: ISO 8601 compliance
* **Epochs**: Unix timestamp, custom epochs
* **Durations**: Session time, intervals

[[biblical-foundation]]
== Biblical Foundation

[NOTE]
====
*Schemas are "just weights."* They ensure we measure honestly — data that claims to be valid actually is valid.
====

_"A false balance is abomination to the LORD: but a just weight is his delight."_ — *Proverbs 11:1 KJV*

_"A false balance is an abomination to Yahweh, but accurate weights are his delight."_ — *Proverbs 11:1 WEB*

*Applied:* A "false balance" is data that claims validity but isn't — a HealthScore of 300, a timestamp of "yesterday", a key without proper format. Schemas prevent false balances. They are the "accurate weights" that ensure honest measurement throughout the system.
