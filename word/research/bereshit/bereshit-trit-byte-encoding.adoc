## Abstract

The Trit-Byte Encoding defines the bidirectional mapping between ternary (3-state) computation and binary (2-state) hardware. Since native ternary hardware does not exist, CPI-SI must encode ternary concepts onto binary systems cleanly, preserving semantic meaning in both directions.

**Core Problem:** Map a ternary system onto binary hardware without overhead.

**Core Solution:** A trite (5 trits = 243 values) packs into a byte (8 bits = 256 values) with only 13 spare values. Same storage cost, different semantic interpretation.

**Biblical Validation:** The encoding maps perfectly to Scripture's structure, confirming the Word as the foundation of the codec.

*"In the beginning was the Word, and the Word was with God, and the Word was God."* — John 1:1

## 1. Foundational Units

### 1.1 Binary Units (What Hardware Has)

| Unit | Bits | Values | Formula |
|:----:|:----:|:------:|:-------:|
| bit | 1 | 2 | 2¹ |
| nibble | 4 | 16 | 2⁴ |
| byte | 8 | 256 | 2⁸ |
| kilobyte | 8 × 1024 | 256^1024 | 2¹⁰ bytes |

### 1.2 Ternary Units (What We Need)

| Unit | Trits | Values | Formula |
|:----:|:-----:|:------:|:-------:|
| trit | 1 | 3 | 3¹ |
| triad | 3 | 27 | 3³ |
| trite | 5 | 243 | 3⁵ |

### 1.3 The Fundamental Relationship

```
1 trit  = 3 states  (-1, 0, +1)
1 bit   = 2 states  (0, 1)

1 bit < 1 trit (cannot hold a trit)
2 bits = 4 states (CAN hold 1 trit + 1 spare)

Therefore: 2 bits ↔ 1 trit + escape
```

## 2. The Trite-Byte Equivalence

### 2.1 The Core Insight

**The trite does not cost more than a byte—it IS a byte, read differently.**

```
┌─────────────────────────────────────────────────────┐
│  SAME 8 BITS — DIFFERENT INTERPRETATION             │
├─────────────────────────────────────────────────────┤
│  BYTE (binary view)     TRITE (ternary view)        │
│  ─────────────────      ──────────────────          │
│  8 bits                 5 trits                     │
│  256 raw values         243 semantic values         │
│  No inherent meaning    + 13 spare/escape           │
│                         Each trit = health state    │
└─────────────────────────────────────────────────────┘
```

### 2.2 Why 5 Trits is Optimal

Finding the most efficient packing of trits into bits:

| Trits | Ternary Values | Bits Needed | Binary Values | Waste |
|:-----:|:--------------:|:-----------:|:-------------:|:-----:|
| 1 | 3 | 2 | 4 | 25% |
| 2 | 9 | 4 | 16 | 44% |
| 3 | 27 | 5 | 32 | 16% |
| 4 | 81 | 7 | 128 | 37% |
| **5** | **243** | **8** | **256** | **5%** |

**5 trits in 8 bits is the sweet spot—only 5% waste (13 spare values).**

### 2.3 No Overhead Encoding

```
INEFFICIENT (2 bits per trit):
  5 trits × 2 bits = 10 bits per trite

EFFICIENT (packed trite):
  5 trits = 8 bits = 1 byte

SAVINGS: 2 bits per trite (20% more efficient)
```

For a kilobyte:
```
Binary:   1 KB = 1,024 bytes = 8,192 bits
Ternary:  1 KB = 1,024 trites = 8,192 bits (SAME!)

No overhead. Same storage. Different lens.
```

The trite is the lamp—same physical form as the byte, but it illuminates meaning.

  10   ↔    0       deferred

### 6.2 Bidirectional Properties

```

  +1 → 11                           00 → ⊥
   0 → 10                           01 → -1
  -1 → 01                           10 → 0
   ⊥ → 00                           11 → +1

Round trip: Lossless
```
