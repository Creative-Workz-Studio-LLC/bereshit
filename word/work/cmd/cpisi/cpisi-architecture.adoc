--
Architecture documentation for the `cmd/cpisi` command — the **multi-accessible
interface** for the CPI-SI state machine.

*"Their appearance and their work was as a wheel in the middle of a wheel."* — Ezekiel 1:16

**Design Principles:**

1. **Local First** — Runs on the machine. No cloud dependency.
2. **Agnostic** — Logic in packages, not locked to any UI framework.
3. **Easy to Transpile** — State file as API. Any language can consume.
--

== Overview

=== The Core Architecture

All logic lives in the packages. The command is just a **view layer**.

[source]
----
┌─────────────────────────────────────────────────────────────┐
│                      LOGIC LAYER                            │
│                                                             │
│  pkg/statemachine  — 27 positions, 3 commands, 9 operators  │
│  pkg/coordinates   — Bible coordinate mapping               │
│  pkg/cpisi/...     — Schema, compute, bereshit              │
│                                                             │
│              ALL LOGIC LIVES HERE (Platform Agnostic Go)    │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ↓
                 ┌─────────────────┐
                 │   STATE FILE    │  ~/.claude/state/position.json
                 │  (the contract) │  JSON — any language can read
                 │                 │  Local — no cloud needed
                 └────────┬────────┘
                          │
                          ↓
                 ┌─────────────────┐
                 │     DAEMON      │  Background watcher
                 │  (the connector)│  Makes state "live" across all views
                 └────────┬────────┘
                          │ watches & notifies
        ┌─────────────────┼─────────────────┬─────────────────┐
        ↓                 ↓                 ↓                 ↓
   ┌─────────┐      ┌─────────┐      ┌─────────┐      ┌─────────┐
   │   CLI   │      │   TUI   │      │   GUI   │      │Statusline│
   │ Machine │      │ Terminal│      │ Visual  │      │ Ambient │
   │ Scripts │      │ Active  │      │ Future  │      │  HUD    │
   └─────────┘      └─────────┘      └─────────┘      └─────────┘
----

=== Why This Architecture

[cols="1,3"]
|===
|Principle |Implementation

|**Local First**
|State file on disk. No server. No cloud. Works offline.

|**Agnostic**
|GUI tech doesn't matter. Logic isn't in the view. State file is the API.

|**Transpilable**
|Go compiles to WASM. JSON is universal. Any future target works.
|===

**Game Design Parallel:**

- **Game State** = `pkg/statemachine` (the truth)
- **HUD** = Statusline (ambient awareness)
- **Menus** = TUI (focused interaction)
- **Console** = CLI (developer/scripting)
- **Render Engine** = GUI (visual presentation)

Same engine, multiple render backends.

== The Five Interfaces

=== CLI — Machine Friendly

**Purpose:** Scripts, hooks, automation.

**Key Commands:**
[source,bash]
----
cpisi status              # One-shot: show current state
cpisi set PAST-PRESENT    # Set position (hooks use this)
cpisi psi 1.5             # Calculate Ψ(N)
cpisi explore constants   # Explore the system
cpisi compute demo        # Geometric computation demo
----

**Design Requirements:**

- Exit codes (0=success, 1=error)
- JSON output option (`--json`)
- Parseable, predictable output
- No TTY required

=== TUI — Human Interactive

**Purpose:** Development, exploration, active interaction.

**Features:**
- Mode tabs (Navigate, Ψ(N), Bible)
- Color-coded positions (HALT=red, AWAIT=yellow, PROCEED=green)
- Keyboard navigation
- Real-time state updates

**Tech:** Bubble Tea (bubbletea + lipgloss)

=== GUI — Visual Future

**Purpose:** Pre-production visualization, demos, user-facing.

**Design Requirements:**

- Local first (no web server required for basic use)
- Agnostic (logic NOT in the GUI code)
- Reads/writes state file (same as CLI/TUI)
- Daemon notifies of changes

**Tech Options (future, not locked in):**

[cols="1,2,2"]
|===
|Option |Pros |Cons

|Fyne
|Pure Go, cross-platform
|Less mature ecosystem

|Gio
|Pure Go, immediate mode
|Learning curve

|WASM + Web
|Familiar tech, transpilable
|Needs browser or webview

|Wails/Tauri
|Native + web hybrid
|More dependencies
|===

**Key Insight:** The choice doesn't matter NOW because logic is in packages and
state file is the contract. We can swap GUI tech without touching core logic.

=== Statusline — Ambient Awareness

**Purpose:** Always-visible cognitive state in terminal.

**Integration Point:** Reads state file, displays in Claude Code statusline.

**What to Add:**
[source]
----
🧭 PRESENT-PRESENT [AWAIT] @  ← Position, Command, Operator
----

**Location:** `statusline/cmd/statusline/main.go`

The statusline already shows identity, time, git, etc. Adding cognitive state
means reading from `~/.claude/state/position.json` and formatting for display.

=== Daemon — The Connector

**Purpose:** Background watcher that makes state "live" across all interfaces.

**How It Works:**

1. Watches `~/.claude/state/position.json`
2. On change, can trigger:
   - TUI refresh
   - GUI notification
   - Statusline update (via hook)
   - Any registered callback

**Current Implementation:** `cpisi daemon` — watches file, displays live state.

**Future:** Could use inotify/fsnotify for efficient watching.

== Interface Communication

=== The Flow

[source]
----
Hook fires (e.g., tool/pre-use)
    ↓
Hook calls: cpisi set PAST-PRESENT "hook:tool/pre-use"
    ↓
State file updated
    ↓
Daemon sees change
    ↓
Daemon can notify:
    • TUI (if running) — refresh display
    • GUI (if running) — update view
    • Statusline — next render shows new state
----

=== Event Types

[cols="1,2,2"]
|===
|Event |Source |Consumers

|Position change
|`cpisi set`, TUI, GUI
|Daemon → all views

|Anchor change
|`cpisi anchor`, TUI
|Daemon → all views

|Ψ(N) calculation
|`cpisi psi`, TUI
|Display only (no state change)
|===

== Summary

The `cpisi` command implements the **multi-accessible interface** pattern:

1. **Logic in packages** — `pkg/statemachine`, `pkg/coordinates`, `pkg/cpisi/*`
2. **State file as API** — `~/.claude/state/position.json`
3. **Daemon as connector** — Watches state, notifies views
4. **Multiple views** — CLI (machine), TUI (interactive), GUI (visual), Statusline (ambient)

**Local first. Agnostic. Transpilable.**

The GUI tech choice is intentionally deferred because it doesn't matter — the
architecture ensures any frontend can consume the same state file and use the
same packages.
