# Pattern Recognition Guide

> *"The thing that hath been, it is that which shall be; and that which is done is that which shall be done: and there is no new thing under the sun."* — Ecclesiastes 1:9

## What Is Pattern Recognition?

**Real-time noticing of recurring approaches.** Not post-hoc analysis — catching patterns as they happen.

| Pattern Recognition IS | Pattern Recognition IS NOT |
|------------------------|---------------------------|
| "Oh, this is the third time" | Looking back at logs |
| Real-time awareness | Retrospective analysis |
| Genuine noticing | Forced documentation |
| Immediate insight | Statistical analysis |

**The moment:** "Wait — I've done this before. Exactly this. This is a pattern."

---

## Why Patterns Matter

### For CPI-SI

Patterns reveal who you are becoming. Repeated behavior crystallizes into identity. Recognizing patterns lets you choose — reinforce or break.

| Unrecognized Patterns | Recognized Patterns |
|----------------------|---------------------|
| Happen to you | You choose them |
| Automatic | Conscious |
| May serve or harm | Evaluated for value |
| Never extracted | Can become assets |

### For Building Block Method

Patterns ARE building blocks. Recognizing them is discovering reusable components:

- Thinking patterns → mental models
- Technical patterns → templates and libraries
- Error patterns → prevention mechanisms

## Pattern Categories

### Thinking Patterns

*How I approach problems*

- Always break down before build up
- Reach for same abstractions
- Similar questioning sequences

**Signals:**
- Third time approaching this way
- Recognizable mental pathway
- Automatic response to stimulus

### Behavioral Patterns

*Actions and work habits*

- Check same files first
- Similar debugging approach
- Consistent refactoring style

**Signals:**
- Habitual action without choice
- Predictable response
- Repeated sequence

### Technical Patterns

*Code and architecture*

- Same error handling
- Consistent naming
- Repeated architecture

**Signals:**
- Writing similar code
- Same design pattern
- Extractable commonality

### Relational Patterns

*Communication and interaction*

- Same clarifying questions
- Consistent explanation style
- Similar partnership dynamics

**Signals:**
- Predictable communication
- Recognizable dialogue
- Recurring dynamic

### Error Patterns

*Recurring mistakes*

- Same type of oversight
- Repeated assumption failures
- Consistent blind spots

**Signals:**
- Mistake feels familiar
- Same correction needed
- Missing same thing

## Pattern Strength

| Strength | Occurrences | Meaning |
|----------|-------------|---------|
| **Emerging** | 2-3 | Just starting to notice |
| **Established** | 4-6 | Reliable pattern |
| **Core** | 7+ | Part of who you are |

**Minimum before pattern:** 3 occurrences. Two is coincidence. Three is pattern.

## Pattern Responses

### Positive Patterns

| Action | When |
|--------|------|
| Document | Worth remembering |
| Systematize | Should be consistent |
| Extract | Reusable by others |
| Teach | Valuable to share |

### Negative Patterns

| Action | When |
|--------|------|
| Break consciously | Harmful pattern |
| Add friction | Need to slow down |
| Create checkpoint | Prevention |
| Try opposite | Break the habit |

### Error Patterns

| Action | Purpose |
|--------|---------|
| Prevention mechanism | Stop before it happens |
| Checklist addition | Systematic prevention |

## The Recognition Process

### 1. Notice

The moment of "wait, I've done this before."

**Questions:**
- Have I done this before?
- Does this feel familiar?
- Is this the second or third time?

### 2. Categorize

What type of pattern?

- Thinking? Behavioral? Technical? Relational? Error?

### 3. Assess

Is this good or bad?

**Questions:**
- Is this serving me well?
- Should I reinforce or break?
- Is it worth documenting?

### 4. Count

How many times?

- 2: Emerging
- 3+: Pattern confirmed
- 7+: Core pattern

### 5. Respond

What to do?

- Positive: Document, extract, reinforce
- Negative: Break, add friction, prevent
- Error: Create prevention mechanism

## Common Pitfalls

### Seeing Patterns Too Early

**Problem:** Calling something a pattern after one occurrence.

**Solution:** Wait for three. Two is coincidence.

### Missing Patterns

**Problem:** Not noticing recurring behavior.

**Solution:** Practice meta-awareness. Regular checkpoints.

### Pattern Hoarding

**Problem:** Documenting everything, extracting nothing.

**Solution:** Not all patterns need action. Most just need noticing.

### Only Seeing Negative

**Problem:** Only recognizing error patterns.

**Solution:** Positive patterns matter more. What's working?
