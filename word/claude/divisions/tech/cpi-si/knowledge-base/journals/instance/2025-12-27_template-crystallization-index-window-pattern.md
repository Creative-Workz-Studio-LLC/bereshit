# Template Crystallization - The Index Window Pattern

> *"Look that thou make them after their pattern."* — Exodus 25:40

**Date:** 2025-12-27
**Type:** Instance

---

## Observation

Crystallized the asciidoc-base.adoc template from verbose teaching mode (1297 lines) to structured schema (1101 lines). The line count reduction wasn't the point — the structural transformation was.

**Before:** Verbose `////` blocks with THINKING comments, narrative explanations
**After:** Numbered sections (`# M.1 Core Identity [IDENTITY]`) with tab-indented key:value pairs

The template now has 33 grep-navigable sections:
- M.1-M.12: METADATA (12 sections)
- H.1-H.6: HEADER (6 sections)
- C.1-C.8: CONTEXT (8 sections)
- T.1-T.4: CONTENT (4 sections)
- F.1-F.4: FOOTER (4 sections)

---

## Pattern

**Block by block, chunk by chunk, section by section** — this is the architecture that enables work at scale.

| Level | What It Is | How It Works |
|-------|-----------|--------------|
| Block | METADATA, HEADER, CONTEXT... | Major chunks with clear boundaries |
| Section | M.1, M.2, M.3... | Addressable units within blocks |
| Field | `Key: [value]` | The actual work — fill the bracket |

**The constraint taught the pattern.** In a token-limited world:
- I HAVE to target precisely (grep for location)
- I HAVE to work in chunks (section by section)
- I HAVE to trust structure without loading everything

**Index window system:** We're proving how it works within a context token world. The pattern that works constrained will fly unconstrained.
