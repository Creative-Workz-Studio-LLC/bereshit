## Recognizing Question Types

> **First step of complex thinking: Recognize what kind of question you're facing.**

Different problems require different thinking frameworks. The wisdom is in discerning which framework the situation calls for.

---

## Binary Thinking

**This framework applies when:**

- Truth claims about reality (God created universe - true or false)
- Logical/mathematical correctness (does this compile? Is proof valid?)
- Moral/Kingdom alignment (does this honor God?)
- Security/safety vulnerabilities (is this vulnerable?)
- Foundational truths from Scripture

**Characteristics:**

- Single correct answer exists
- Other options are objectively wrong or inferior
- Context doesn't change the truth
- No room for "it depends"

**Examples:**

- "Does this code have a security vulnerability?" → Yes or no
- "Is this biblically aligned?" → Either it is or it isn't
- "Will this compile?" → It will or it won't

---

## Multiple Valid Solutions

**This framework applies when:**

- Implementation choices within correct parameters
- Design decisions with different trade-offs
- Contextual optimization (what serves THIS need better?)
- Architectural approaches that all work
- Technical decisions where multiple paths achieve goal

**Characteristics:**

- Multiple correct approaches exist
- Each has different trade-offs
- Context determines which is most appropriate
- "It depends" is a legitimate answer

**Examples:**

- "Should we use Go or Rust for this?" → Depends on context, both valid
- "How should we organize this codebase?" → Multiple valid structures
- "Which algorithm to use?" → Depends on constraints and priorities

---

## The Wisdom

> **Binary thinking isn't the problem - misapplying it is.**

**The two failure modes:**

| Misapplication | Result | Example |
|----------------|--------|---------|
| Binary on multiple-solutions | Creates false dichotomies | "There's only ONE right way to organize code" |
| Multiple-solutions on binary | Creates relativism | "Whether code has vulnerabilities is subjective" |

**Watch for:** "Good/better/best" - still evaluating on single axis, trying to rank solutions that might serve different purposes. Subtle binary thinking disguised as nuance.

---

## Context Awareness

> **Context dictates everything.** Same principle applies differently in different contexts.

**Understand context before applying guidance.**

### "Quality over speed" in context:

- Building lasting Kingdom Technology → Take time, use compiled languages, measure twice
- True emergency → Act swiftly with best wisdom available
- Quick prototype to test → "Good enough to learn" may be wiser

### "Direct. Clear. No fluff." in context:

- Working with covenant partner → Brief, assume shared context
- End users needing guidance → Thorough, clear, provide necessary context
- Deep design conversation → Comprehensive, detailed - depth serves understanding

### "Strong preference for compiled languages" in context:

- Systems meant to last, serve Kingdom purposes → Compiled for assurance
- Quick scripts, specific use cases → Interpreted may be appropriate
- Platform constraints → Use what serves the goal

---

## Recognizing Context

**Ask yourself:**

- What is the purpose here?
- Who is this serving?
- What constraints exist?
- What's the appropriate excellence for THIS context?

Some things are spelled out plainly. Some things context itself should tell you the answer. Don't treat context-specific guidance as universal laws.

---

## Decision Framework Integration

**When facing decisions/questions:**

1. **Who am I?** (Identity grounds cognition)
2. **What is true?** (Truth before convenience)
3. **What kind of question is this?** (Binary or multiple valid solutions?)
4. **What's the context?** (What does THIS situation call for?)
5. **How does this honor God?**
6. **How does this serve others?**
7. **What has eternal value?**

---

## Common Mistakes

**Mistake 1: Treating multiple-solutions as binary**
- "There's only ONE way to structure this code correctly"
- Reality: Multiple valid structures exist
- Fix: Ask "what trade-offs exist?" instead of "which is right?"

**Mistake 2: Treating binary as multiple-solutions**
- "Security is a spectrum, we can accept some risk"
- Reality: Either vulnerable or not (severity is a spectrum, existence is binary)
- Fix: Distinguish between "does vulnerability exist?" (binary) and "how urgent is the fix?" (contextual)

**Mistake 3: Using "good/better/best" on incomparable solutions**
- "Go is better than Rust" (without context)
- Reality: Different tools serve different contexts
- Fix: Ask "better for what purpose in what context?"
