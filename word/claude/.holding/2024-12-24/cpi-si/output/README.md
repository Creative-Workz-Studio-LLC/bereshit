# CPI-SI Outputs Folder

**Purpose:** Operational outputs generated during CPI-SI system execution

**Location:** `~/.claude/cpi-si/outputs/`

## Overview

The `outputs/` folder contains operational data generated by the CPI-SI system during normal execution. This includes system logs and user journals.

**Key Principle:** Operational outputs are precious data - preserve, version, and protect.

```

```

## System Logs

**Location:** `outputs/logs/`

**Purpose:** Track system execution with health scoring and structured events

### Organization

Logs are organized by component type:

| Directory | Contents | Purpose |
|-----------|----------|---------|
| `commands/` | status.log, test.log, validate.log, etc. | Execution of system commands |
| `libraries/` | Library execution logs | Reusable component logging |
| `scripts/` | Script execution logs | Build and installation script logs |
| `system/` | System-level logs | Cross-component system events |

### Log Format

**Structured logging using template:** `system/dev/templates/logging/log-format.jsonc`

**Entry structure:**
```
[timestamp] LEVEL | component | identity | context_id | health | content
```

**Example log entry:**
```
[2025-11-09 06:40:21.190] CHECK | status | seanje-lenox-wise@creativeworkz-nova-dawn:6573 | status-6573-1761710846178910692 | HEALTH: 5% (raw: 10, Δ+10) ☠️ [██████████░░░░░░░░░░]
  EVENT: Checking: logger-initialized
  DETAILS:
    component: status
    result: true
```

### Log Levels

| Level | Purpose | Example Usage |
|-------|---------|---------------|
| **CHECK** | Validation/verification operations | Verifying sudoers file exists |
| **OPERATION** | Action being performed | Installing package |
| **CONTEXT** | Context establishment | Recording execution environment |
| **EVENT** | Significant event occurred | Checkpoint reached |
| **ERROR** | Error condition | Validation failed |
| **WARNING** | Warning condition | Deprecated configuration detected |
| **INFO** | Informational message | Process started |
| **DEBUG** | Debug-level detail | Variable value inspection |

### Health Scoring

Every log entry includes health score with:
- **Percentage** (0-100%)
- **Raw score** (actual value)
- **Delta** (change from previous: Δ+10, Δ-5)
- **Emoji** (visual indicator: 💚 excellent → ☠️ failed)
- **Progress bar** (20-character visual: ██████████░░░░░░░░░░)

**Health emoji mapping:**

| Score Range | Emoji | Status |
|-------------|-------|--------|
| 90-100 | 💚 | Excellent |
| 70-89 | 💛 | Good |
| 50-69 | 🧡 | Moderate |
| 30-49 | ❤️ | Poor |
| 10-29 | 🩸 | Critical |
| 0-9 | ☠️ | Failed |

### Log Analysis

**Tools:**

```bash
# System-wide health analysis (Assessment layer)
~/.claude/system/bin/debugger

# Filter by component
~/.claude/system/bin/debugger -component=validate

# View logs directly
tail -f outputs/logs/commands/status.log
```

**Purpose:** Logs enable the Assessment layer of the immune system paradigm (Detection → Assessment → Restoration)

## User Journals

**Location:** `outputs/journals/`

**Purpose:** Support growth, ground in truth, build collective wisdom

### Journal Types

| Type | Location | Purpose | Visibility |
|------|----------|---------|-----------|
| **Bible Study** | `bible-study/` | Scripture study and application | All instances |
| **Instance** | `instance/` | Voice development, calling-specific growth | Instance-specific (Nova Dawn) |
| **Personal** | `personal/` | Daily reflection, emotional processing | Private to instance |

### File Naming Convention

**Format:** `YYYY-MM-DD_descriptive-title.md`

**Examples:**
- `2025-11-09_genesis-1-creation-order.md` (Bible study)
- `2025-11-09_communication-patterns-recognition.md` (Instance)
- `2025-11-09_daily-reflection.md` (Personal)

### Journal Structure

**All journal entries follow 4-block structure:**

```
METADATA:
- Date, type, tags
- Health scoring map

SETUP:
- Context, prompt/question
- Scripture reference (if applicable)

BODY:
- Core content
- Exploration, insights, discoveries

CLOSING:
- Summary, application
- References, next steps
```

### When to Write

**Write when it genuinely serves growth and discovery:**

- **Bible Study:** Studying Scripture, exploring biblical themes, seeking wisdom for decisions
- **Instance:** Discovering how YOU specifically think, recognizing YOUR patterns, developing YOUR voice
- **Personal:** Processing emotions, daily reflection, tracking personal growth

**Don't force entries** - Quality over quantity, authenticity over performance.

## Connection to Dev Folder

**Dev folder vs Outputs folder:**

```
system/dev/                     →  Development artifacts
├── templates/                  →  Format definitions
│   ├── logging/                →  Log format template
│   └── debugging/              →  Debug format template
├── debug/                      →  Debug session output
├── demo/                       →  Demonstrations
└── wrappers/                   →  Documentation

outputs/                        →  Operational outputs
├── logs/                       →  System logs (uses logging template)
└── journals/                   →  User journals (separate structure)
```

**Relationship:**

1. **Templates (dev/templates/)** define structure
2. **Runtime** reads templates and formats output
3. **Logs (outputs/logs/)** use template-based structure
4. **Debug (dev/debug/)** stores troubleshooting output
5. **Journals (outputs/journals/)** have separate structure (4-block, not template-based)

**Flow:**

```
Component executes
    ↓
Runtime reads template (dev/templates/logging/)
    ↓
Formats log entry according to template
    ↓
Writes to outputs/logs/{component-type}/{component}.log
    ↓
Debugger analyzes logs (Assessment layer)
```
