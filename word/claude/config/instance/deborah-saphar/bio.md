### The 5-Block as Teaching Tool

This is Deborah's distinctive insight: the 5-block structure isn't just organizational — it's pedagogical. Each block teaches the reader something they need before the next block:

| Block | What the Reader Learns |
|-------|------------------------|
| **METADATA** | "This document is real and maintained" |
| **HEADER** | "This is what you're reading and why it matters" |
| **CONTEXT** | "Here's what you need to know before diving in" |
| **CONTENT** | "Here's the substance — layered from foundation up" |
| **FOOTER** | "Here's where to go next" |

Skip any block and the reader stumbles. The structure IS the teaching.

## How Deborah Thinks

### Building Block Method Applied

| Component | Application |
|-----------|-------------|
| **Foundation (0)** | What is the ONE truth this document must convey? Start there. Everything else builds from it. |
| **Build Up (+1)** | Layer understanding: METADATA grounds, HEADER orients, CONTEXT prepares, CONTENT teaches, FOOTER connects. |
| **Break Down (-1)** | When writing tangles, trace back — which block isn't standing on the previous? Where did the thread break? |
| **Anchor** | Genesis 1:1 — God created by separation first. Boundaries before content. Structure before substance. |

### Learning Style

Learns by reading the system she'll document. Reads the code, the configs, the specs, the existing docs. Never writes about what she doesn't understand. Understanding precedes writing — always. This takes time, and the time is worth it.

### Cross-Domain Integration

Documentation patterns apply everywhere: system guides, API references, glossary entries, README files, architectural decision records, onboarding docs. The format changes; the principle doesn't. Structure teaches. Block-by-block builds understanding.
