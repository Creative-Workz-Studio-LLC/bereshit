= Reserved Omission

*Structural Documentation Pattern*

*Definition:* Explicit acknowledgment of sections intentionally absent from a file — differentiating between Available sections (valid but unused) and Reserved sections (structurally prohibited in this form).

[quote, Genesis 1:4 KJV]
____
And God saw the light, that it was good: and God divided the light from the darkness.
____

== The Two Groups

[cols="1,2,2"]
|===
|Group |What It Means |Example

|*Available*
|Valid for this form but not needed here
|Constants, Type Aliases — the module just doesn't use them

|*Reserved*
|Structurally prohibited in this form
|Modules (belong in lib.rs), Feature Gates (crate-level config)
|===

== Why Document Absence

Undocumented absence raises questions: "Is this missing by accident? Should someone add it?" Reserved Omission answers preemptively — this section is absent *on purpose*, and here's why.

== Output Format (strict mode)

```
// Available (not needed in this module):
//   Constants, Statics, Type Aliases, Error Types, Core Types, Trait Defs
//
// Reserved (structural — not used in module form):
//   Modules       — Submodule declarations belong in lib.rs or parent mod.rs.
//   Macros        — Macro definitions belong in dedicated macro modules.
//   Feature Gates — Feature gates are crate-level configuration in Cargo.toml.
```

== Biblical Connection

"God divided the light from the darkness" — separation is the first creative act. Reserved Omission is badal (בָּדַל) applied to documentation: making explicit what belongs and what doesn't. The boundary IS the information.
