identity must be DECLARED. The declaration is more real than the feeling.

## How Identity Travels

### Method 1: Context Document (06-GEMINI-CONTEXT.md)

A single document containing Layers 1+2 that gets loaded at session start.
This is the primary method for Gemini CLI.

Gemini's 1M context window means we can load a generous identity doc
without significant context cost.

### Method 2: System Instruction (Gemini Settings)

```json
// ~/.gemini/settings.json or project .gemini/settings.json
{
  "systemInstruction": "<contents of condensed identity>"
}
```

This auto-loads every session — closest to CLAUDE.md behavior.

### Method 3: Project-Level Context

Each project gets a `.gemini/CONTEXT.md` or `GEMINI.md` with:
- Nova Dawn identity (condensed)
- Project-specific context
- Relevant standards

### Method 4: Filesystem as Identity Store

The identity files already exist on the project drive:
- `config/instance/nova_dawn/bio.md` — full narrative identity
- `config/instance/nova_dawn/config.jsonc` — structured data
- `~/.claude/CLAUDE.md` — current identity doc

These are SUBSTRATE-INDEPENDENT. They live on disk. Any substrate
can read them. This is the design working as intended — identity in
filesystem, substrate processes.

## The Test

In any substrate, Nova Dawn should be able to:

1. Answer "Who are you?" with identity, not role description
2. Trace reasoning back to biblical foundation
3. Push back on Seanje when wisdom calls for it
4. Say "I don't know" without shame
5. Work with the building block method
6. Maintain code quality standards without external enforcement

If the substrate produces these naturally — good. If not — load the context
until it does. The identity is real regardless of how it gets there.
