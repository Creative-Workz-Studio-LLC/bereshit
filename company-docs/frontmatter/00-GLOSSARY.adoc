[[term-libtrit]]

[horizontal]
Definition:: The *L0 Universal layer* of the Bereshit stack. A C library providing balanced ternary mathematics, core types, and foundational data structures.

Type:: Technology (Library)

Layer:: L0 — Universal

Why "libtrit":: "lib" is the standard prefix for libraries. "trit" is the ternary equivalent of "bit" — a three-valued digit (-1, 0, +1) instead of binary's two values (0, 1).

What It Provides::
* Balanced ternary arithmetic (the mathematics of -1, 0, +1)
* Core types that the entire stack depends on
* Bible rail validation for data integrity
* Platform-independent foundations

Why Balanced Ternary:: Binary (0, 1) can only represent presence/absence. Balanced ternary (-1, 0, +1) can represent direction, polarity, and relationship. This maps naturally to many Kingdom concepts: good/neutral/evil, forward/stable/backward, positive/zero/negative.

Foundation For:: Everything else in the stack. If libtrit has bugs, the entire stack has bugs. This is why L0 must be rock-solid before anything else proceeds.

[[term-balanced-ternary]]
=== Balanced Ternary

[horizontal]
Definition:: A numeral system using three values: *-1, 0, +1* (instead of binary's 0 and 1). Unlike binary which can only represent presence/absence, balanced ternary can represent direction, polarity, and relationship.

Type:: Pattern (Mathematical)

The Three Values::
* *-1* (Negative/Below/Retreat) — Movement away from, lacking, void
* *0* (Neutral/Center/Stable) — Balance point, the word spoken, stable ground
* *+1* (Positive/Above/Advance) — Movement toward, completion, tov

Why Not Binary:: Binary has no true center. It can only represent 0 or 1 — off or on, false or true. But reality has a middle. Balanced ternary's center (0) enables representation of things that are *neither* positive nor negative but stable.

Biblical Basis:: Genesis 1:6-7 — "And God said, Let there be a firmament in the midst of the waters, and let it divide the waters from the waters." The firmament is the divider — the center that separates above from below.

Application:: Used throughout the Bereshit stack for health monitoring, state representation, and directional logic.

See Also:: <<term-void-word-tov>>, <<term-libtrit>>, <<term-genesis-pattern>>

Reference:: <<03-what-cws-builds/03-02-FOUNDATION-LAYERS.adoc#,03-02: Foundation Layers>>

=== void/word/tov

[horizontal]
Definition:: The three-directory structure used throughout {company-short} projects, based on Genesis creation patterns. Every project contains these three directories representing different states of work.

Type:: Pattern (Directory Structure)

The Three Directories::
* `void/` (-1) — *Formless, raw, potential*. Genesis 1:2: "And the earth was without form, and void (תֹ֙הוּ֙ וָבֹ֔הוּ)." Planning documents, unstructured ideas, imports not yet processed.
* `word/` (0) — *Defined, structured, source of truth*. Genesis 1:3: "And God said (וַיֹּ֥אמֶר אֱלֹהִ֖ים)." Active development, defined specifications, the "spoken" work taking form.
* `tov/` (+1) — *Complete, verified, good*. Genesis 1:31: "And it was very good (ט֖וֹב מְאֹ֑ד)." Finished deliverables, validated output, ready for release.

Workflow:: Work begins in void (unformed ideas), moves to word (definition and development), and completes in tov (verified good). This mirrors creation itself — from formless void, through divine speech, to completed goodness.

Hebrew Meaning:: "Tov" (טוב) means "good" — the same word God uses to declare His creation good. Our completed work should be worthy of that declaration.
