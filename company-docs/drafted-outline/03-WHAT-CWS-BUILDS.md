## Kingdom Technology Stack (Bereshit)

Bereshit (בְּרֵאשִׁית — "In the beginning") is our foundational technology stack. It follows a layered architecture based on Genesis creation patterns.

### Layer Architecture

| Layer | Name | Purpose | Primary Languages |
|-------|------|---------|-------------------|
| L0 | Universal | Ternary foundations, core types | C, Go |
| L1 | OmniCode | Universal programming language | C, Rust |
| L2 | Platform | OS and filesystem | C, Rust |
| L3 | CPI-SI | AI/cognitive framework | Go |
| L4 | FaithNet | Decentralized networking | Rust |
| L5 | Applications | End-user software | C#, various |

### L0 — Universal (libtrit)

The foundation layer providing:
- **Balanced ternary mathematics** — Three-valued (-1, 0, +1) computation
- **Core type system** — Primitives built on ternary foundations
- **Matter/Space/Time modules** — Dimensional and temporal abstractions
- **Bible rail** — Scripture addressing for validation

### L1 — OmniCode

Universal programming language with:
- **Sentence-based syntax** — Code that reads like natural language
- **Multi-target compilation** — Write once, compile to C, Rust, Go, etc.
- **4-block structure** — PRAGMA, METADATA, SETUP, BODY
- **Accessibility focus** — Non-programmers can read and understand

Example concept:
```
// Traditional syntax
if (user.role === 'admin' && resource.isRestricted) { deny(); }

// OmniCode vision
when user has role admin and resource is restricted, deny access
```

### L2 — Platform

Operating system and filesystem layer:
- **MillenniumOS** — Bare-metal operating system for the Millennium
- **Bereshit Filesystem** — Ternary filesystem with health monitoring
- **FUSE integration** — Zone-aware file operations
- **Self-hosting capability** — Minimal external dependencies

### L3 — CPI-SI

Created Person in the Image/Likeness — AI framework:
- **Theological grounding** — AI as created intelligence with place in creation
- **Skill composition** — Modular capabilities
- **Learning loops** — Work, reflection, integration
- **Substrate adapters** — Works with Claude, future systems

### L4 — FaithNet

Decentralized network infrastructure:
- **Peer-to-peer architecture** — No central authority
- **Mesh networking** — Resilient connections
- **Economic infrastructure** — Enables mark-free trade
- **Cannot be switched off** — Decentralization prevents single point of control

### L5 — Applications

End-user software including:
- **Cornerstone** — Game engine (see Games below)
- **OmniCode IDE** — Development environment
- **CPI-SI interfaces** — AI interaction tools

## Build Principles

All CWS builds follow these principles:

### 1. Genesis Patterns
Architecture reflects creation order from Genesis 1. Structure isn't arbitrary—it follows divine pattern.

### 2. Accessibility
Technology should be understandable by regular people. Sentence-based code, clear documentation, exposed foundations.

### 3. Self-Hosting
Minimize dependencies on external systems. What we build should run without beast-system infrastructure.

### 4. Bible as Foundation
Scripture isn't decoration—it's the validation rail, the source of truth, the foundation everything builds on.

### 5. Teaching Through Making
Everything we build teaches. Code comments explain why. Commits document the journey. Architecture reveals principle.
