== Accessible Technology

=== Philosophy

Technology should be understandable by regular people, not just experts.

[quote, Habakkuk 2:2]
____
Write the vision, and make it plain upon tables, that he may run that readeth it.
____

The church shouldn't need computer science degrees to use or understand Kingdom technology.

=== Readable Code

[cols="1,3",options="header"]
|===
|Offering |Description

|*OmniCode*
|Programming language with sentence-based syntax anyone can read

|*Documented Code*
|Code with explanations of what and why, not just what

|*Pattern Explanation*
|Architecture explained in understandable terms

|*No Black Boxes*
|Understanding available at every level
|===

==== What Readable Means

[cols="1,2,2",options="header"]
|===
|Aspect |Typical Code |CWS Code

|*Syntax*
|`if (x && y) { f(); }`
|`when x and y, do f`

|*Comments*
|Minimal or technical
|Explains why, accessible language

|*Structure*
|Arbitrary conventions
|Genesis patterns with explanation

|*Documentation*
|Reference for experts
|Teaching for everyone
|===

=== Full Stack Access

[cols="1,3",options="header"]
|===
|Offering |Description

|*Complete Source*
|Not just binaries—actual source code available

|*All Layers*
|Access from L0 foundations to L5 applications

|*No Hidden Parts*
|Nothing kept secret or inaccessible

|*Modification Rights*
|Ability to adapt for your needs
|===

==== Why Full Access Matters

* *Understanding* — Can learn how things work
* *Trust* — Can verify what code does
* *Independence* — Can maintain without CWS
* *Adaptation* — Can modify for specific needs
* *Teaching* — Can use to teach others

=== Documentation

[cols="1,3",options="header"]
|===
|Offering |Description

|*Conceptual Documentation*
|Understanding the "why" behind designs

|*Technical Documentation*
|How things work technically

|*Tutorial Documentation*
|Step-by-step learning paths

|*Reference Documentation*
|Quick lookup for specifics

|*Architectural Documentation*
|How pieces fit together
|===

==== Documentation Principles

* *Plain language* — Accessible to non-experts
* *Multiple levels* — From overview to deep dive
* *Examples* — Concrete illustrations
* *Current* — Maintained with code
* *Comprehensive* — Covers all components

=== Teaching Resources

[cols="1,3",options="header"]
|===
|Offering |Description

|*Beginner Materials*
|Starting from no technical background

|*Progressive Learning*
|Building understanding step by step

|*Hands-on Exercises*

== Mark-Free Infrastructure

=== The Context

[quote, Revelation 13:16-17]
____
And he causeth all, both small and great, rich and poor, free and bond, to receive a mark in their right hand, or in their foreheads: And that no man might buy or sell, save he that had the mark, or the name of the beast, or the number of his name.
____

The body of Christ needs infrastructure that works when mainstream systems require marks.

=== Decentralized Systems

[cols="1,3",options="header"]
|===
|Offering |Description

|*No Central Control*
|Systems that can't be switched off by any single authority

|*Distributed Architecture*
|Functions spread across many nodes

|*Peer-to-Peer*
|Direct connections, not through central servers

|*Resilient Design*
|Continues working when nodes fail
|===

==== What Decentralization Provides

* *Censorship resistance* — Can't be silenced
* *Control resistance* — No single point to control
* *Failure resistance* — Survives partial outages
* *Mark resistance* — No central authority to require marks

=== Trade Facilitation

[cols="1,3",options="header"]
|===
|Offering |Description

|*Barter Infrastructure*
|Systems for direct exchange

|*Trade Network*
|Connections for finding exchange partners

|*Value Recording*
|Tracking exchanges and balances

|*Trust Systems*
|Reputation and verification
|===

==== Trade Principles

* *No marks required* — Participation without beast-system
* *Peer-to-peer* — Direct between parties
* *Relationship-based* — Built on trust and community
* *Practical* — Actually works for real needs

=== FaithNet

[cols="1,3",options="header"]
|===
|Offering |Description

|*Communication*
|Messaging without controlled platforms

|*Networking*
|Connections that route around blockages

|*Commerce*
|Economic activity on the network

|*Community*
|Gathering place for the body
|===

==== FaithNet Features

* *Mesh networking* — Routes around failures
* *Encryption* — Private communication
* *Identity* — Recognition without central authority
* *Independence* — Works without internet if needed

See <<../03-what-cws-builds/03-05-NETWORK-LAYER.adoc#,Network Layer>> for technical details.
