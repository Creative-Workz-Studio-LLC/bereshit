== Overview

Build system for the *CreativeWorkzStudio LLC Company Identity Manual* —
a board-level governance document structured as a legal hierarchy with
four Parts, eleven Articles, and eighty-seven Sections.

Built with GNU Make and https://docs.asciidoctor.org/asciidoctor/latest/[Asciidoctor PDF].

*Capabilities:*

* Four editorial build scopes (book, part, article, section)
* Unified 3-mode path resolution on all scoped targets
* Layered validation with legal hierarchy enforcement
* 57-check editorial lint across 7 categories (editorial, style, structure, conversion, legal, tone, industry)
* Theme validation against typographic and page-layout standards
* Editorial watch mode for live PDF rebuild
* Five PDF themes (manual-legal, manual, legal, plain, informal)
* Letter-based spine and section naming throughout


== Quick Start

[source,bash]
----
# Install dependencies (first time only)
make setup

# Check that everything is available
make deps

# Build full book PDF
make book

# Validate legal hierarchy
make validate TYPE=manual-l

# See all targets
make help
----


== Document Hierarchy

The manual follows a legal governance structure.
Each level maps to a distinct filesystem convention:

[cols="^1,2,2,3",options="header"]
|===
|Depth |Level |Rendered Label |Filesystem Convention

|1
|Part
|Part I, Part II, Part III, Part IV
|Directory: `Part-{N}-{name}/`

|2
|Article
|Article 1, Article 2 ... Article 11
|Directory: `Article-{NN}-{name}/`

|3
|Section
|§ 1.1, § 1.2, § 2.1
|File: `{LETTER}-{NAME}.adoc`

|4
|Subsection
|§ 1.1.1, § 1.1.2
|Heading within file (`====`)

|5
|Clause
|—
|Heading within file (`=====`)
|===

*Naming rules:*

* Section letters are *sequential* within each article: A, B, C, D — no gaps
* Every article begins with Section A (the article overview)
* Part numbers are Arabic (1, 2, 3, 4); Article numbers are zero-padded (01, 02 ... 11)
* Directory names use lowercase with hyphens; section file names use uppercase with hyphens
* Subsections and below exist within section files as AsciiDoc headings

Rendered section numbers are auto-generated by Asciidoctor (`:sectnums:`).
The letter-based filesystem convention is for the editorial team and build system.

== Build Scopes

Four levels of granularity for editorial review.
All output mirrors the book spine under `build/output/`.

[cols="1,3,2",options="header"]
|===
|Scope |Command |Output

|*Full Book*
|`make book` or `make create`
|`build/output/CWS-Company-Identity-Manual.pdf`

|*Part*
|`make part PART=1`
|`build/output/B-content/Part-1-identity/CWS-Part1-Identity.pdf`

|*Article*
|`make article ARTICLE=01`
|`build/output/.../Article-01-.../CWS-Article-01.pdf`

|*Section*
|`make section FILE=A-COVER`
|`build/output/A-frontmatter/A-COVER.pdf`
|===

== Path Resolution

All scoped targets share a unified 3-mode resolution engine.
You never have to remember the exact path.

[cols="1,2,3",options="header"]
|===
|Mode |Detection |Example

|*Path*
|Input contains `/`
|`make part PART=B-content/Part-1-identity`

|*Search*
|Input has no `/`
|`make part PART=1` (ID) or `make part PART=identity` (name)

|*Compat*
|Input starts with `book/`
|`make section FILE=book/A-frontmatter/A-COVER` (prefix stripped)
|===

*Search cascade:*

. *Exact name* — matches the full directory or file name
. *Prefix + ID* — matches `Part-{ID}-\*` or `Article-{ID}-*`
. *Fuzzy* — case-insensitive `\*{input}*` match

Extensions (`.adoc`) and trailing slashes are handled automatically.


== Validation

Layered validation system with three independent dimensions.

[source,bash]
----
make validate                                # Base skeleton
make validate TYPE=manual                    # Book type minimums
make validate TYPE=manual-l                  # Legal hierarchy naming
make validate TYPE=manual   BONUS=operational  # Full editorial
make validate TYPE=manual-l BONUS=operational  # Full legal + editorial
----


=== Base (Skeleton)

Always runs. Checks that the minimum file structure exists:

* `book/book.adoc` — master assembly file
* Spine folders: `A-frontmatter/`, `B-content/`, `C-appendices/`, `D-backmatter/`
* Theme file (`build/themes/cws-manual-legal-theme.yml`)
* Shared attributes file (`build/_previews/_shared-attributes.adoc`)


=== TYPE=manual

Bare minimums for a manual-type book:

* At least one Part directory in `B-content/`
* At least one Article directory in any Part
* At least one `.adoc` content file


=== TYPE=manual-l

Legal hierarchy validation — superset of `manual`.
Enforces the naming conventions defined in the editorial style guide:

* Part directories match `Part-{N}-{name}/` pattern
* Article directories match `Article-{NN}-{name}/` pattern
* Section files match `{LETTER}-{NAME}.adoc` pattern
* Letters are sequential within each article (A, B, C — no gaps)
* No old number-prefix files remain
* Produces a complete file inventory with per-article section counts and letter ranges


=== BONUS=operational

Full editorial checks specific to this operational manual:

* Frontmatter, appendices, and backmatter directories have content
* Assets directory exists
* Preview files exist for each Part
* No empty Article directories
* Naming convention consistency (letter-based vs number-based)
* Per-Part article counts and per-Article section counts


== Asset Generation

The `assets` target runs a 3-phase pipeline to generate all derived visual assets:

[source,bash]
----
make assets              # Generate (skips up-to-date assets)
make assets FORCE=1      # Force regeneration
----

*Phases:*

. *Diagrams* — Mermaid `.mmd` sources → PNG (3x) + SVG per figure (`mmdc`)
. *Grayscale* — Color PNGs → grayscale variants for print fidelity (`magick`)
. *Palette* — Brand colors → color palette swatch image (`magick`)

Requires: `mmdc` (Mermaid CLI) and `magick` (ImageMagick).
Phase 1 runs independently; Phases 2–3 require ImageMagick.

See `book/00-assets/README.adoc` for the full Asset Catalog.

make status    # Show all PDFs, sizes, timestamps, staleness

=== Editorial Workflow

[source,bash]
----
# Watch for changes, auto-rebuild book PDF (requires entr)
make watch-pdf

# Check all dependencies (required + optional)
make deps

# Safe targeted removal
make remove SCOPE=A          # Remove frontmatter output
make remove FILE=A-COVER     # Remove single section output

# Remove all generated output and temp files
make clean

# Install required dependencies
make setup
----

`watch-pdf` uses https://github.com/eradman/entr[entr] to monitor all `.adoc` and `.yml` files,
rebuilding the full book PDF on every save. Pair with a PDF viewer that auto-reloads
(Evince, Okular, or Zathura) for real-time editorial review.

=== Publishing (TypeScript Builder)

Multi-format output via the TypeScript builder (`cws-build`).
Requires separate setup with `make setup-node`.

[source,bash]
----
make html      # Build HTML format
make pdf       # Build PDF via builder
make epub      # Build EPUB format
make docbook   # Build DocBook XML
----

The TypeScript builder also provides structural and editorial tools:

[source,bash]
----
# Structure & inventory
cws-build spine              # Show book structure tree
cws-build inventory          # Show book parts list
cws-build validate           # Validate book structure
cws-build assets             # Generate derived assets (same pipeline as Makefile)

# Editorial lint — 57 checks across 7 categories
cws-build lint               # All 57 checks on all files
cws-build lint --file F      # Lint a single file
cws-build lint --scope A     # Lint a scope (A-frontmatter, B-content, etc.)
cws-build lint --category C  # Filter by category (editorial, style, structure,
                             #   conversion, legal, tone, industry)
cws-build lint --tone        # Shorthand for --category tone
cws-build lint --industry    # Shorthand for --category industry
cws-build lint --bible       # Bible verse validation (KJV/WEB)
cws-build lint --toc         # TOC page marker validation

# TOC pipeline
cws-build toc                # Parse and display TOC structure
cws-build toc --fill         # Fill page number placeholders
cws-build toc --verify       # Check page numbers against computed

# Configuration management
cws-build config             # Show resolved configuration
cws-build config --validate  # Validate all 18 config sections
cws-build config --types     # Generate TypeScript types from YAML
cws-build config --make      # Regenerate config.mk from YAML
----


== Exit Codes

Every error message includes its code tag (`[E1]`, `[E2]`, etc.)
for quick identification. Make reports the recipe exit code in its
`Error N` line.

[cols="^1,2,3",options="header"]
|===
|Code |Name |Meaning

|*E0*
|Success
|Target completed without errors

|*E1*
|Usage error
|Missing or invalid arguments (`PART=`, `ARTICLE=`, `FILE=`)

|*E2*
|Missing dependency
|Required tool or source file not found

|*E3*
|Build failure
|`asciidoctor-pdf` returned a non-zero exit code

|*E4*
|Validation failure
|Structure checks found errors (`validate` target only)

|*E10–E19*
|Config errors
|Missing config file, invalid YAML, required section absent

|*E20–E29*
|Validation errors
|Structure validation failures (builder `validate` command)

|*E30–E39*
|Editorial lint
|Lint check failures (57 checks across 7 categories)
|===
