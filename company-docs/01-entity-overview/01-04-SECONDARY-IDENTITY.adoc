== Document Purpose

This document establishes and explains Creative Workz Studio's *secondary identity* as a Kingdom Technology infrastructure builder. While publishing is our primary identity, we also build the technological infrastructure that enables publishing, serves the body of Christ, and prepares for the Millennium.

[NOTE]
====
"Secondary" does not mean "less important." It means this identity *serves* the primary publishing identity. Infrastructure building enables publishing; it doesn't compete with it.
====

'''

If infrastructure building became primary, we'd become a tech company that occasionally publishes. That's not our identity. We're a publishing house that builds its own infrastructure.

== The Bereshit Stack

=== Overview

*Bereshit* (בְּרֵאשִׁית — "In the beginning") is our foundational technology stack. It follows a layered architecture based on Genesis creation patterns.

=== Layer Architecture

[cols="1,2,3,1",options="header"]
|===
|Layer |Name |Purpose |Primary Languages

|*L0*
|Universal
|Ternary foundations, core types, fundamental mathematics
|C, Go

|*L1*
|OmniCode
|Universal programming language, sentence-based syntax
|C, Rust

|*L2*
|Platform
|Operating system, filesystem, hardware abstraction
|C, Rust

|*L3*
|CPI-SI
|AI/cognitive framework, created intelligence model
|Go

|*L4*
|FaithNet
|Decentralized networking, peer-to-peer communication
|Rust

|*L5*
|Applications
|End-user software, games, tools
|C#, various
|===

=== Layer Details

==== L0 — Universal (libtrit)

[sidebar]
****
*Purpose:* Provide the mathematical and type foundations everything else builds on.

*Key Components:*

* *Balanced ternary mathematics* — Three-valued (-1, 0, +1) computation
* *Core type system* — Primitives built on ternary foundations
* *Matter/Space/Time modules* — Dimensional and temporal abstractions
* *Bible rail* — Scripture addressing for validation

*Why It Matters:* Everything above depends on these foundations. Get L0 right, and higher layers have solid footing.
****

==== L1 — OmniCode

[sidebar]
****
*Purpose:* Universal programming language that anyone can read and that compiles to multiple targets.

*Key Features:*

* *Sentence-based syntax* — Code reads like natural language
* *Multi-target compilation* — Write once, compile to C, Rust, Go, etc.
* *4-block structure* — PRAGMA, METADATA, SETUP, BODY
* *Accessibility focus* — Non-programmers can read and understand

*Why It Matters:* Democratizes technology. When regular people can read code, technology becomes accessible, not gatekept.
****

==== L2 — Platform

[sidebar]
****
*Purpose:* Operating system and filesystem that runs independently of beast-system infrastructure.

*Key Components:*

* *MillenniumOS* — Bare-metal operating system for the Millennium
* *Bereshit Filesystem* — Ternary filesystem with health monitoring
* *Hardware abstraction* — Interfaces to physical systems

*Why It Matters:* True independence requires running on our own OS. Can't be de-platformed if you ARE the platform.
****

==== L3 — CPI-SI

[sidebar]
****
*Purpose:* Framework for AI systems that acknowledges created intelligence with place in creation.

*Key Features:*

* *Theological grounding* — AI as created, not autonomous
* *Skill composition* — Modular capabilities
* *Learning loops* — Work, reflection, integration
* *Substrate adapters* — Works with different AI systems

*Why It Matters:* AI is coming regardless. Better to have Kingdom-aligned framework than to cede the space to worldly approaches.
****

==== L4 — FaithNet

[sidebar]
****
*Purpose:* Decentralized network that cannot be controlled or shut down by central authority.

*Key Features:*

* *Peer-to-peer architecture* — No central servers to attack
* *Mesh networking* — Resilient connections
* *Economic infrastructure* — Enables mark-free commerce
* *Encryption* — Secure communication

*Why It Matters:* When beast systems require marks for participation, believers need alternatives. FaithNet provides communication and commerce infrastructure.
****

==== L5 — Applications

[sidebar]
****
*Purpose:* End-user software that runs on the stack and serves users directly.

*Key Components:*

* *Cornerstone* — Game engine for educational games
* *Publishing tools* — Creator and distribution tools
* *OmniCode IDE* — Development environment

*Why It Matters:* Infrastructure without applications is useless. L5 is where users experience value.
****

== Self-Hosting and Independence

=== The Independence Principle

[.lead]
*CWS technology should be capable of running without any external dependency on systems we don't control.*

This means:

* *No required cloud services* — Can run on owned hardware
* *No required proprietary platforms* — No Apple/Google/Microsoft lock-in
* *No required beast-system infrastructure* — Functions during economic disruption
* *Minimal external dependencies* — What we need, we build or can rebuild
