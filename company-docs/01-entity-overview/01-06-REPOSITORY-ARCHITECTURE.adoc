== icon:sitemap[] Repository Hierarchy

=== icon:eye[] Overview

{company-short} work is organized in a hierarchy of Git repositories with submodule relationships:

[source]
----
CWS Repo (Creative Workz Studio — company level)
│
└── Bereshit Repo (Kingdom Technology foundation)
    │
    ├── CPI-SI for Claude Repo (AI integration framework)
    │
    └── Cornerstone Repo (Game engine)
----

=== icon:clipboard-list[] Hierarchy Principles

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Principle |Application

|icon:folder[role=blue]
|*Parent Contains Child*
|Higher-level repos include lower-level as submodules

|icon:cube[role=green]
|*Child Can Stand Alone*
|Each repo is complete and functional independently

|icon:user-shield[role=purple]
|*Clear Ownership*
|Each repo has defined ownership and responsibility

|icon:share-alt[role=orange]
|*Shareable Components*
|Submodules can be shared with external parties without exposing parent

|icon:thumbtack[role=gold]
|*Version Pinning*
|Parent pins specific versions of submodules for stability
|===

== icon:puzzle-piece[] Submodule Architecture

=== icon:info-circle[] What Are Submodules

Git submodules allow one repository to include another at a specific version:

[cols="^1,4",frame=all,grid=all]
|===
|icon:link[role=blue]
|Parent repo references child repo at a specific commit

|icon:shield-alt[role=green]
|Child repo maintains full independence

|icon:sync[role=purple]
|Parent can update to newer child versions deliberately

|icon:lock[role=orange]
|Changes to child don't automatically affect parent
|===

=== icon:check-double[] Submodule Benefits

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Benefit |Description

|icon:thumbtack[role=blue]
|*Version Stability*
|Parent pins specific version; unexpected changes don't break parent

|icon:code-branch[role=green]
|*Independent Development*
|Child repo can evolve without coordinating every change

|icon:share-alt[role=purple]
|*Selective Sharing*
|Can share child without exposing parent

|icon:border-all[role=orange]
|*Clear Boundaries*
|Defined interfaces between components

|icon:users[role=gold]
|*Distributed Ownership*
|Different teams can own different repos
|===

=== icon:clipboard-check[] Submodule Practices

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Practice |Description

|icon:thumbtack[role=blue]
|*Pin to Stable*
|Parent should reference tested, stable child versions

|icon:sync[role=green]
|*Deliberate Updates*
|Update child references intentionally, not automatically

|icon:file-alt[role=purple]
|*Document Versions*
|Track why specific versions are pinned

|icon:vial[role=orange]
|*Test After Updates*
|Verify parent still works after child version updates

|icon:comments[role=gold]
|*Coordinate Breaking Changes*
|Communicate when child changes break parent expectations
|===

'''

== icon:layer-group[] Code Organization Principles

=== icon:sitemap[] Layered Architecture (L0-L5)

Code within Bereshit follows the layered architecture:

[source]
----
word/work/
├── pkg/
│   ├── trit/         (L0 — Universal)
│   ├── omni/         (L1 — OmniCode)
│   ├── fuse/         (L2 — Platform/Filesystem)
│   ├── foundation/   (L0/L3 — Core foundations)
│   └── ...
├── cmd/              (CLI tools)
└── ...
----

=== icon:arrow-down[] Dependency Direction

[IMPORTANT]
.icon:exclamation-circle[] Dependency Rule
====
*Dependency Rule:* Higher layers depend on lower layers. Lower layers NEVER depend on higher layers.

[cols="^1,4",frame=all,grid=all]
|===
|icon:5[role=gold]
|L5 may import L4, L3, L2, L1, L0

|icon:4[role=purple]
|L4 may import L3, L2, L1, L0

|icon:3[role=blue]
|L3 may import L2, L1, L0

|icon:2[role=green]
|L2 may import L1, L0

|icon:1[role=orange]
|L1 may import L0

|icon:0[role=gray]
|L0 depends on nothing (foundational)
|===
====

=== icon:cube[] Module Organization

Each module should:

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Principle |Application

|icon:bullseye[role=blue]
|*Single Responsibility*
|One clear purpose per module

|icon:border-all[role=green]
|*Clear Interface*
|Defined public API, hidden implementation

|icon:file-alt[role=purple]
|*Documentation*
|README, code comments, usage examples

|icon:vial[role=orange]
|*Tests*
|Unit tests, integration tests as appropriate

|icon:shield-alt[role=gold]
|*Independence*
|Minimal dependencies, especially across layers
|===
