== Overview

[sidebar]
.Biblical Foundation
****
[quote, Habakkuk 2:2]
____
"Write the vision, and make it plain upon tables, that he may run that readeth it."
____

The builder serves two modes: editorial review for page-by-page refinement,
and multi-format publishing for final distribution. Both are config-driven —
behavior lives in YAML, code just executes.
****

=== Dual Build Architecture

The build system operates in two modes, each optimized for its purpose:

[cols="^1h,3,3",options="header",frame=all,grid=all]
|===
| Mode | Primary (Editorial) | Secondary (Publishing)

| Engine
| Makefile + asciidoctor-pdf
| TypeScript builder + build.config.yaml

| Purpose
| Page-by-page editorial review
| Multi-format final output

| Formats
| PDF only (scoped previews)
| PDF, HTML, EPUB, DocBook, manpage

| Scopes
| Full book, Part, Article, Section
| Full book only

| Entry point
| `make <target>`
| `cws-build [command]`
|===

The Makefile is the primary editorial tool — fast, scoped PDF builds for
review. The TypeScript builder handles multi-format publishing and adds
editorial intelligence: spine scanning, inventory tracking, and structure
validation.

=== Editorial Commands (NEW in 2.0)

[cols="2,4",options="header",frame=all,grid=all]
|===
| Command | Description

| `cws-build inventory`
| Show complete parts list with file counts and letter ranges

| `cws-build spine`
| Display full book structure tree (every file in every article)

| `cws-build validate`
| Base skeleton validation (book.adoc, spine dirs, theme, attributes)

| `cws-build validate -t manual-l`
| Legal hierarchy naming validation (Part/Article/Section patterns)

| `cws-build validate -t manual-l -b operational`
| Full editorial validation (assets, previews, naming consistency)
|===

== Quick Start

[TIP]
====
All Make commands run from `company-docs/`. +
All `cws-build` commands run from `company-docs/build/builder/`.
====

=== Editorial Review (Primary)

[source,bash]
----
# From company-docs/
make book              # Full book PDF
make A                 # Frontmatter only
make B                 # All content Parts
make part PART=1       # Single Part
make article ARTICLE=01  # Single Article
make validate TYPE=manual-l BONUS=operational  # Full validation
----

=== Publishing & Editorial Intelligence (Secondary)

[source,bash]
----
# From company-docs/build/builder/
node dist/cli.js inventory           # Parts list
node dist/cli.js spine               # Structure tree
node dist/cli.js validate -t manual-l  # Validation
node dist/cli.js --format pdf        # Build PDF
node dist/cli.js --format all        # Build all formats
node dist/cli.js --check             # Check prerequisites
----

=== npm Script Shortcuts

[source,bash]
----
# From company-docs/build/builder/

# Editorial (delegates to Makefile)
npm run editorial:book               # make book
npm run editorial:frontmatter        # make A
npm run editorial:content            # make B
npm run editorial:validate           # make validate TYPE=manual-l
npm run editorial:validate:full      # make validate TYPE=manual-l BONUS=operational
npm run editorial:watch              # make watch-pdf

# Publishing (delegates to TS builder)
npm run publish:pdf                  # Build PDF
npm run publish:html                 # Build HTML
npm run publish:all                  # Build all formats
npm run publish:check                # Check prerequisites
npm run publish:info                 # Show output file info
----

Output files appear in `company-docs/build/output/`.

== Configuration

All builder behavior is defined in `build/build.config.yaml` — the TypeScript
code is just an executor. To change behavior, edit the config file.

=== Config Sections

[cols="1,4",options="header",frame=all,grid=all]
|===
| Section | Purpose

| `document`
| Master file path, output filename, output directory

| `attributes`
| AsciiDoc attributes passed as `-a key=value` to Asciidoctor

| `formats`
| Output format definitions (command, backend, extension, install hint)

| `watch`
| File patterns, ignore patterns, debounce timing for watch mode

| `display`
| Banner toggle, color toggle, icon map for CLI output

| `assets`
| Required asset files (logo, etc.) with specifications

| `version`
| Config version (currently 2.0.0)
|===

=== Canonical Attribute Sources

[cols="2,4",options="header",frame=all,grid=all]
|===
| File | Role

| `build/build.config.yaml`
| TS builder attributes (publishing)

| `build/_previews/_shared-attributes.adoc`
| Preview build attributes (editorial)

| `book/book.adoc`
| Master assembly attributes (full book)
|===

All three must stay in sync. The editorial style guide
(`editorial-style-guide.adoc`, CWS-GDE-001) is the specification.

== CLI Reference

=== Publishing Options (Default Action)

[cols="2,4",options="header",frame=all,grid=all]
|===
| Option | Description

| `-f, --format <format>`

| Clean output directory before building

| Build formats in parallel

| Check prerequisites without building

| `-q, --quiet`
| Suppress banner and non-essential output

=== Editorial Subcommands

==== `cws-build inventory`

Shows a complete parts list with file counts and section letter ranges.

[source]
----
Book Inventory
==============

  Frontmatter: 5 files
  Appendices: 4 files
  Backmatter: 3 files

  Content:
    Part 1 (identity): 2 articles, 15 sections
      Art. 01 (entity-overview): 8 sections (A–H)
      Art. 02 (publishing-house-model): 7 sections (A–G)
    ...

  Summary:
    4 parts, 11 articles, 87 sections
    99 total files (1.6 MB)
----

==== `cws-build spine`

Displays the full book structure tree — every scope, part, article, and
section file.

==== `cws-build validate [options]`

Three-layer validation matching the Makefile's `validate` target:

[cols="2,4",options="header",frame=all,grid=all]
|===
| Option | Layer

| (none)
| Base skeleton — book.adoc, spine dirs, theme, attributes

| `-t manual`
| Manual minimums — parts, articles, content files exist

| `-t manual-l`
| Legal hierarchy — Part/Article/Section naming conventions, sequential letters

| `-b operational`
| Bonus — scope content, assets, previews, naming consistency
|===

Exit code 4 on validation failure (matches Makefile convention).

== Programmatic Usage

The builder exports a full library API for integration:

[source,typescript]
----
import {
  // Config
  loadConfig, computePaths, type BuildConfig, type RuntimePaths,

  // Spine
  scanSpine, buildInventory, type SpineTree,

  // Validation
  runValidation, type ValidationResult,

  // Publishing
  createBuilder, type BuildResult,

  // Display
  formatFileSize, formatDuration,
} from '@cws/manual-builder';

// Load config and compute paths
const config = loadConfig();
const paths = computePaths(config);

// Scan the book spine
const tree = await scanSpine(paths.bookDir);
const inventory = buildInventory(tree);

// Validate structure
const result = await runValidation(paths, { type: 'manual-l' });

// Build formats
const builder = createBuilder(config, paths);
const results = await builder.build(['pdf', 'html']);
----

=== Module Responsibilities

[cols="2,4",options="header",frame=all,grid=all]
|===
| Module | Responsibility

| `config/`
| Loads `build.config.yaml`, validates required sections, computes runtime paths,
  provides query functions (enabled formats, format config, icons)

| `spine/`
| Walks the `book/` directory tree, discovers all 4 scopes (A-D), parts,
  articles, and sections. Builds structured inventory reports with counts,
  sizes, and letter ranges

| `validate/`
| Three-layer validation: base skeleton, book type minimums (manual, manual-l),
  bonus editorial checks (operational). Matches Makefile's `validate` target

| `publish/`
| Executes format builds via Asciidoctor CLI tools. Sequential or parallel
  execution. File watching with configurable debounce

| `display/`
| Config-driven CLI output: startup banner, build progress events, file size
  and duration formatting
|===

== Governance Hierarchy

The Company Identity Manual uses a 6-level legal hierarchy:

[cols="^1,2,3",options="header",frame=all,grid=all]
|===
| Level | Element | Filesystem Pattern

| 1
| Part
| `Part-{N}-{name}/`

| 2
| Article
| `Article-{NN}-{name}/`

| 3
| Section
| `{LETTER}-{NAME}.adoc`

| 4
| Subsection
| (within section files)

| 5
| Clause
| (within section files)

| 6
| Subclause
| (within section files)
|===

The `validate -t manual-l` command enforces levels 1-3 at the filesystem
level. Levels 4-6 exist within AsciiDoc heading structure.
