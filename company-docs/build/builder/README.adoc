== Overview

[sidebar]
.Biblical Foundation
****
[quote, Habakkuk 2:2]
____
"Write the vision, and make it plain upon tables, that he may run that readeth it."
____

The builder serves two modes: editorial review for page-by-page refinement,
and multi-format publishing for final distribution. Both are config-driven —
behavior lives in YAML, code just executes.
****

=== Dual Build Architecture

The build system operates in two modes, each optimized for its purpose:

[cols="^1h,3,3",options="header",frame=all,grid=all]
|===
| Mode | Primary (Editorial) | Secondary (Publishing)

| Engine
| Makefile + asciidoctor-pdf
| TypeScript builder + build.config.yaml

| Purpose
| Page-by-page editorial review
| Multi-format final output

| Formats
| PDF only (scoped previews)
| PDF, HTML, EPUB, DocBook, manpage

| Scopes
| Full book, Part, Article, Section
| Full book only

| Entry point
| `make <target>`
| `cws-build [command]`
|===

The Makefile is the primary editorial tool — fast, scoped PDF builds for
review. The TypeScript builder handles multi-format publishing and adds
editorial intelligence: spine scanning, inventory tracking, and structure
validation.

=== Editorial Commands

[cols="2,4",options="header",frame=all,grid=all]
|===
| Command | Description

| `cws-build inventory`
| Show complete parts list with file counts and letter ranges

| `cws-build spine`
| Display full book structure tree (every file in every article)

| `cws-build validate`
| Base skeleton validation (book.adoc, spine dirs, theme, attributes)

| `cws-build validate -t manual-l`
| Legal hierarchy naming validation (Part/Article/Section patterns)

| `cws-build validate -t manual-l -b operational`
| Full editorial validation (assets, previews, naming consistency)

| `cws-build lint`
| Editorial lint — 57 checks in 7 categories (editorial, style, structure, conversion, legal, tone, industry)

| `cws-build lint --category C`
| Filter by category: editorial, style, structure, conversion, legal, tone, industry

| `cws-build lint --tone`
| Shorthand for `--category tone` (covenant language, plain language, sentence length)

| `cws-build lint --industry`
| Shorthand for `--category industry` (document register, creator agreements)

| `cws-build lint --bible`
| Bible verse validation — check citations against KJV/WEB scripture data

| `cws-build lint --toc`
| Page marker validation — sequence, banners, content-full markers

| `cws-build toc`
| Parse and display TOC structure with page status

| `cws-build toc --fill`
| Fill `p. __` placeholders with computed page numbers

| `cws-build toc --verify`
| Check existing page numbers against computed values

| `cws-build config`
| Inspect, validate, or regenerate derived config files (--show, --validate, --types, --make)

| `cws-build assets`
| Generate derived visual assets (diagrams, grayscale, palette)
|===

== Quick Start

[TIP]
====
All Make commands run from `company-docs/`. +
All `cws-build` commands run from `company-docs/build/builder/`.
====

=== Editorial Review (Primary)

[source,bash]
----
# From company-docs/
make book              # Full book PDF
make A                 # Frontmatter only
make B                 # All content Parts
make part PART=1       # Single Part
make article ARTICLE=01  # Single Article
make validate TYPE=manual-l BONUS=operational  # Full validation
----

=== Publishing & Editorial Intelligence (Secondary)

[source,bash]
----
# From company-docs/build/builder/
node dist/cli.js inventory           # Parts list
node dist/cli.js spine               # Structure tree
node dist/cli.js validate -t manual-l  # Validation
node dist/cli.js --format pdf        # Build PDF
node dist/cli.js --format all        # Build all formats
node dist/cli.js --check             # Check prerequisites
----

=== npm Script Shortcuts

[source,bash]
----
# From company-docs/build/builder/

# Editorial (delegates to Makefile)
npm run editorial:book               # make book
npm run editorial:frontmatter        # make A
npm run editorial:content            # make B
npm run editorial:validate           # make validate TYPE=manual-l
npm run editorial:validate:full      # make validate TYPE=manual-l BONUS=operational
npm run editorial:watch              # make watch-pdf

# Publishing (delegates to TS builder)
npm run publish:pdf                  # Build PDF
npm run publish:html                 # Build HTML
npm run publish:all                  # Build all formats
npm run publish:check                # Check prerequisites
npm run publish:info                 # Show output file info
----

Output files appear in `company-docs/build/output/`.

== Configuration

All builder behavior is defined in `build/build.config.yaml` — the TypeScript
code is just an executor. To change behavior, edit the config file.

=== Config Sections (18 + version)

*Required* — must be present for the builder to start:

[cols="2,5",options="header",frame=all,grid=all]
|===
| Section | Purpose

| `document`
| Master file path, output filename, output directory

| `attributes`
| AsciiDoc attributes passed as `-a key=value` to Asciidoctor

| `formats`
| Output format definitions (PDF, HTML, EPUB, DocBook, manpage, Markdown, DOCX)

| `watch`
| File patterns, ignore patterns, debounce timing for watch mode

| `display`
| Banner toggle, color toggle, icon map for CLI output
|===

*Optional* — enable additional capabilities when present:

[cols="2,5",options="header",frame=all,grid=all]
|===
| Section | Purpose

| `assets`
| Asset directories, logo catalog, figure pipeline, derived asset generation

| `scripture`
| Bible data path, translation list, default translation (KJV/WEB)

| `paths`
| Override computed paths (output, book, theme directories)

| `scopes`
| Named build scopes (frontmatter, appendices, backmatter) with preview files

| `brand`
| Brand color palette (deep-blue, gold, dark, light, medium-blue)

| `typography`
| Font families, sizes, scale ratio, heading depth, alignment, colors, roles, styles, legal typography, tables/lists/figures styling

| `page_layout`
| Page size, margins, header/footer height, vertical spacing, thematic breaks, heading spacing

| `legal_language`
| Obligation verbs, defined terms, construction rules, binding requirements, amendment tiers, governance notation, cross-references, recitals, numbering, enumeration, boilerplate

| `industry_specific`
| Game development (IP, EULA, three-license) and publishing house (creator agreements, governance) standards

| `tone_and_voice`
| CWS voice attributes, tone spectrum, covenant language replacements, plain language words, closing filler, paragraph density, passive voice, readability targets

| `document_types`
| Document type → register → theme mapping (governance, policy, contract, EULA, guide, etc.)

| `asciidoc_publishing`
| Prohibited attributes, section roles, include guards, page flow rules, required book attributes

| `company_conventions`
| Legal name, raw name variants, board members, contact emails, reading guide parties
|===

Config version: `5.2.0` — run `cws-build config --validate` to verify all sections.

=== Canonical Attribute Sources

==== `cws-build spine`

Displays the full book structure tree — every scope, part, article, and
section file.

==== `cws-build validate [options]`

Three-layer validation matching the Makefile's `validate` target:

[cols="2,4",options="header",frame=all,grid=all]
|===
| Option | Layer

| (none)
| Base skeleton — book.adoc, spine dirs, theme, attributes

| `-t manual`
| Manual minimums — parts, articles, content files exist

| `-t manual-l`
| Legal hierarchy — Part/Article/Section naming conventions, sequential letters

| `-b operational`
| Bonus — scope content, assets, previews, naming consistency
|===

Exit code 4 on validation failure (matches Makefile convention).

== Programmatic Usage

The builder exports a full library API for integration:

[source,typescript]
----
import {
  // Config
  loadConfig, computePaths, type BuildConfig, type RuntimePaths,

  // Spine
  scanSpine, buildInventory, type SpineTree,

  // Validation
  runValidation, type ValidationResult,

  // Publishing
  createBuilder, type BuildResult,

  // Display
  formatFileSize, formatDuration,
} from '@cws/manual-builder';

// Load config and compute paths
const config = loadConfig();
const paths = computePaths(config);

// Scan the book spine
const tree = await scanSpine(paths.bookDir);
const inventory = buildInventory(tree);

// Validate structure
const result = await runValidation(paths, { type: 'manual-l' });

// Build formats
const builder = createBuilder(config, paths);
const results = await builder.build(['pdf', 'html']);
----

'''

=== Module Responsibilities

[cols="2,4",options="header",frame=all,grid=all]
|===
| Module | Responsibility

| `cli/`
| Command-line interface. Thin entry shim + Commander program setup.
  Each subcommand lives in its own file under `commands/`. Shared utilities
  (error exit, Make delegation, format parsing) in `utils.ts`

| `config/`
| Loads `build.config.yaml` (18 sections), validates required sections,
  computes runtime paths, provides query functions. Type generator
  produces TypeScript interfaces from YAML schema. Type bridge provides
  compile-time drift detection between generated and hand-written types

| `spine/`
| Walks the `book/` directory tree, discovers all 4 scopes (A-D), parts,
  articles, and sections. Builds structured inventory reports with counts,
  sizes, and letter ranges

| `validate/`
| All validation: 3-layer structural (base → type → bonus),
  57-check editorial lint (7 categories), theme YAML validation
  (typography, colors, layout), Bible verse verification (KJV/WEB),
  and page/TOC pipeline (fill, verify, cross-validation)

| `publish/`
| Executes format builds via Asciidoctor CLI tools and pandoc pipeline.
  Sequential or parallel execution. File watching with configurable debounce

| `assets/`
| 3-phase derived asset generation: Mermaid diagrams → grayscale variants →
  palette swatch. Timestamp-based caching

| `display/`
| All terminal output formatting: startup banner, build progress,
  and result display for every command (validation, editorial, Bible,
  TOC, spine, assets)

| `errors.ts`
| Cross-cutting error system: typed error codes (E0-E4x), severity levels,
  structured formatting, error collection, section type detection
|===

== Governance Hierarchy

The Company Identity Manual uses a 6-level legal hierarchy:

[cols="^1,2,3",options="header",frame=all,grid=all]
|===
| Level | Element | Filesystem Pattern

| 1
| Part
| `Part-{N}-{name}/`

| 2
| Article
| `Article-{NN}-{name}/`

| 3
| Section
| `{LETTER}-{NAME}.adoc`

| 4
| Subsection
| (within section files)

| 5
| Clause
| (within section files)

| 6
| Subclause
| (within section files)
|===

The `validate -t manual-l` command enforces levels 1-3 at the filesystem
level. Levels 4-6 exist within AsciiDoc heading structure.
