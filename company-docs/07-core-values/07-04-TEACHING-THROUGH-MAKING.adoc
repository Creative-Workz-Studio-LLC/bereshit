== Anti-Patterns

=== Expert-Only

[sidebar]
****
*What It Is:*

Creating things only experts can understand — code, documentation, products that assume advanced knowledge.

*Why It Violates Teaching:*

Teaching reaches learners, not just experts. Expert-only work excludes the people who most need to learn.

*Warning Signs:*

* "They should already know this"
* Jargon without explanation
* Documentation that assumes expertise
* Products requiring extensive prior knowledge
* Impatience with beginners
****

=== Undocumented

[sidebar]
****
*What It Is:*

Creating without documenting — code without comments, processes without explanation, products without guides.

*Why It Violates Teaching:*

Undocumented work can't teach beyond direct interaction. It dies with its creator. It hoards knowledge.

*Warning Signs:*

* "I'll document it later"
* Tribal knowledge only
* New people can't onboard easily
* Original creators must explain everything
* Knowledge lost when people leave
****

=== Teaching as Afterthought

[sidebar]
****
*What It Is:*

Adding documentation or teaching later, after the product is "done" — treating teaching as optional extra.

*Why It Violates Teaching:*

Afterthought documentation is usually incomplete, disconnected, and quickly outdated. Teaching should be designed in, not added on.

*Warning Signs:*

* Documentation phase at end of project
* Teaching materials created by different team
* Products that don't naturally teach
* Constant documentation backlog
* "We'll add tutorials later"
****

== Decision Test

=== The Question

[IMPORTANT]
====
*"Does this teach?"*

This question tests whether what we're creating helps others learn, understand, and eventually do for themselves.
====

=== Applying the Test

[cols="1,3",options="header"]
|===
|Situation |How to Apply

|*Writing Code*
|Can someone learn from reading this?

|*Building Feature*
|Does using this teach the user something?

|*Creating Process*
|Is the reasoning documented?

|*Making Decision*
|Can others learn from our reasoning?

|*Designing Game*
|Does gameplay embed learning?

|===

=== Levels of Teaching

[cols="1,3",options="header"]
|===
|Level |Description

|*Usable*
|Someone can use it (minimum)

|*Understandable*
|Someone can understand how it works

|*Learnable*
|Someone can learn principles from it

|*Transferable*
|Someone can apply lessons elsewhere

|*Teachable*
|Someone can teach others from it

|===

'''
