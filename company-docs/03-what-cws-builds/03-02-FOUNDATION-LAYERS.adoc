=== icon:balance-scale[] Balanced Ternary Mathematics

==== icon:question-circle[] What Is Balanced Ternary?

Balanced ternary uses three values: -1, 0, and +1 (often written as T, 0, 1 or -, 0, +).

[cols="^1,1,2,3",options="header",frame=all,grid=all]
|===
|icon:tag[] |Value |Symbol |Meaning

|icon:arrow-down[role=blue]
|*-1*
|T (or -)
|Negative / Below / Formless

|icon:minus[role=purple]
|*0*
|0
|Zero / Boundary / Firmament

|icon:arrow-up[role=green]
|*+1*
|1 (or +)
|Positive / Above / Complete
|===

==== icon:lightbulb[] Why Ternary?

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Reason |Explanation

|icon:bible[role=blue]
|*Genesis Pattern*
|Reflects the firmament dividing waters above from waters below (Genesis 1:6)

|icon:exchange-alt[role=purple]
|*Natural Negation*
|Negation is simply inverting signs; no separate representation needed

|icon:dot-circle[role=green]
|*Rounding Built-in*
|The center value (0) provides natural rounding point

|icon:balance-scale[role=orange]
|*Balance*
|Symmetric around zero; equally expressive in positive and negative

|icon:tachometer-alt[role=red]
|*Efficiency*
|Mathematically the most efficient radix for representation
|===

==== icon:cog[] Ternary Operations

Basic operations in balanced ternary:

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Operation |How It Works

|icon:plus[role=blue]
|*Addition*
|Sum values with carry handling (-1 + 1 = 0, 1 + 1 = -1 with carry)

|icon:exchange-alt[role=purple]
|*Negation*
|Flip all signs (-1 becomes +1, +1 becomes -1)

|icon:times[role=green]
|*Multiplication*
|Standard multiplication with ternary values

|icon:balance-scale[role=orange]
|*Comparison*
|Natural three-way comparison (-1 less, 0 equal, +1 greater)
|===

=== icon:cubes[] The 4-Block Structure

Every OmniCode file follows a four-block structure:

==== icon:cog[] Block 1: PRAGMA

Configuration and compiler directives:

[source]
----
PRAGMA:
    target: rust
    optimize: size
    strict: true
----

==== icon:info-circle[] Block 2: METADATA

Documentation and context:

[source]
----
METADATA:
    name: "User Authentication"
    author: "Development Team"
    version: "1.0.0"
    scripture: "Proverbs:4:23"
    purpose: "Guard access to protected resources"
----

==== icon:play[] Block 3: SETUP

Declarations and initialization:

[source]
----
SETUP:
    define User as entity with:
        name as text
        role as text
        authenticated as boolean

    define Resource as entity with:
        name as text
        restricted as boolean
----

==== icon:terminal[] Block 4: BODY

The actual executable code:

[source]
----
BODY:
    to check access for a user to a resource:
        when user is not authenticated,
            deny access with message "Please authenticate first"

        when resource is restricted and user has role "guest",
            deny access with message "Insufficient permissions"

        otherwise,
            grant access to the resource
----

=== icon:align-left[] Sentence-Based Syntax

==== icon:gavel[] Syntax Principles

[cols="^1,2,4",options="header",frame=all,grid=all]
|===
|icon:tag[] |Principle |Application

|icon:stream[role=blue]
|*Natural Flow*
|Code reads left-to-right like prose

|icon:cut[role=purple]
|*Minimal Symbols*
|Reduce brackets, parentheses, special characters

|icon:font[role=green]
|*Keywords as Words*
|Use "when" not "if", "and" not "&&"

|icon:indent[role=orange]
|*Implicit Structure*
|Indentation and context determine structure

|icon:running[role=red]
|*Action Phrases*
|"deny access" not "denyAccess()"
|===

==== icon:code[] Syntax Examples

[source]
----
// Control Flow
when condition is true,
    do something
otherwise,
    do something else

// Loops
for each item in the collection,
    process the item

repeat 10 times,
    perform the action

while condition holds,
    continue processing

// Functions
to calculate the total of items:
    start with sum as 0
    for each item in items,
        add item value to sum
    return the sum
----
