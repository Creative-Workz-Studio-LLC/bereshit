== Document Purpose

This document provides detailed coverage of the *Network Layer (L4)* of the Bereshit stack—FaithNet. FaithNet is a decentralized networking infrastructure designed to enable mark-free communication and commerce.

[IMPORTANT]

== L4: Network Layer Overview

=== What Is FaithNet?

FaithNet is decentralized network infrastructure providing:

* *Peer-to-peer communication* — Direct connection without central servers
* *Mesh networking* — Resilient connections that route around failures
* *Economic infrastructure* — Trade and exchange without beast-system dependency
* *Identity without centralization* — Recognition without central authority control

[source]
----
L4: NETWORK LAYER (FAITHNET)

┌─────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │

=== The Mark-Free Imperative

FaithNet exists because of the prophetic warning:

[quote, Revelation 13:16-17]
____
And he causeth all, both small and great, rich and poor, free and bond, to receive a mark in their right hand, or in their foreheads: And that no man might buy or sell, save he that had the mark, or the name of the beast, or the number of his name.
____

FaithNet provides infrastructure so believers can:

* *Communicate* without requiring mark-system accounts
* *Trade* without mark-system financial infrastructure
* *Connect* without mark-system identity verification

== Architecture Principles

=== Decentralization

==== Why Decentralization?

[cols="1,2,2",options="header"]
|===
|Aspect |Centralized |Decentralized (FaithNet)

|*Control*
|Single authority controls access
|No single point of control

|*Failure*
|Single point of failure
|Resilient to node failures

|*Censorship*
|Easy to block or restrict
|Difficult to censor

|*Privacy*
|Central authority sees all traffic
|Traffic distributed across network

|*Mark Requirement*
|Central authority can require mark
|No central authority to require anything
|===

==== Decentralization Model

[source]
----
CENTRALIZED vs DECENTRALIZED:

CENTRALIZED:                    DECENTRALIZED (FAITHNET):

      ┌─────┐                        ○───○───○
      │Central                       │╲ │ ╱│
      │Server│                       ○─○───○─○
      └──┬───┘                       │╱ │ ╲│
    ┌────┼────┐                      ○───○───○
    │    │    │
    ○    ○    ○                 Every node connects
    Users depend on             to multiple peers
    central server
----

=== Peer-to-Peer Communication

==== P2P Model

[cols="1,3",options="header"]
|===
|Feature |Description

|*Direct Connection*
|Peers communicate directly, not through central server

|*Discovery*

|*Routing*

|*Broadcast*

|*Topic-Based*
|Subscription to specific topics/channels
|===

=== Mesh Networking

==== What Is Mesh?

Mesh networking connects nodes in a web where each node can relay for others:

[source]
----
MESH NETWORK:

    ○─────○─────○
    │╲    │    ╱│
    │ ╲   │   ╱ │
    │  ╲  │  ╱  │
    ○────○────○
    │  ╱  │  ╲  │
    │ ╱   │   ╲ │
    │╱    │    ╲│
    ○─────○─────○

If any node fails, messages
route around the failure
----

==== Mesh Benefits

[cols="1,3",options="header"]
|===
|Benefit |Explanation

|*Resilience*
|Network survives individual node failures

|*Self-Healing*
|Routes adjust automatically when topology changes

|*Scalability*
|Adding nodes increases capacity and redundancy

|*Local Communication*
|Nearby nodes can communicate even if internet fails

|*No Single Point*
|No central server to attack or control
|===

== Security Layer

=== Security Principles

[cols="1,3",options="header"]
|===
|Principle |Application

|*End-to-End Encryption*
|Only intended recipients can read messages

|*Perfect Forward Secrecy*
|Past messages safe even if keys compromised

|*Minimal Trust*
|Don't trust nodes you don't need to trust

|*Distributed*
|Security not dependent on single component

|*Open Protocol*
|Security through openness, not obscurity
|===

=== Security Features

[cols="1,3",options="header"]
|===
|Feature |Description

|*Encryption*
|All communication encrypted by default

|*Authentication*
|Verify who you're communicating with

|*Integrity*
|Detect tampering with messages

|*Availability*
|Resist denial-of-service attacks

|*Key Management*
|Secure handling of cryptographic keys
|===
